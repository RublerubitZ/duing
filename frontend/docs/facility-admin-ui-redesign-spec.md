# 시설 예약 관리 콘솔 — UI/UX 개편 최종 화면 스펙 v1

> 기준: 2026-07-20. 목업(총동연 콘솔 JSX v2)을 IA 뼈대로 삼되, 운영자의 실제 사용 루프
> (매일: 검토 / 주 1회: 제출 사이클)를 기준으로 재설계. **현재 기능은 전부 유지**한다.

## 0. 설계 원칙

1. 운영자의 실제 루프는 두 개다: **매일**(검토: 대기 건 훑고 승인/거절) + **주 1회**(제출:
   후보 확인 → 목록 생성 → CSV → 오프라인 제출 → 완료 처리). IA는 이 두 루프의 클릭 수를
   줄이는 방향으로만 바꾼다.
2. 백엔드 도메인 제약(배치=단일 시설, 상태 전이 가드, 사유 필수)은 **UI가 숨기지 않고
   드러낸다**. 목업의 "전체 선택 → 버튼 하나"는 유지하되, 시설별 분해를 다이얼로그에서
   명시한다.
3. 신규 백엔드 기능은 만들지 않는다. additive 필드/필터 4건만 전제로 하고(§11), 각각
   폴백을 둔다.

## 1. 전역 IA — 4단계 워크플로 탭

현행 평면 탭 3개를 **번호+건수가 붙은 워크플로 탭 4개**로 교체한다. 스테퍼처럼 보이지만
동작은 탭이다(어느 단계든 바로 클릭 이동, "진행" 강제 없음 — 운영 루프는 선형이 아니라
순환이므로 목업의 done/현재/미래 시각 구분은 채택하되 이동 제한은 두지 않는다).

| 단계 | URL | 내용 | 건수 출처 |
|---|---|---|---|
| ① 예약 검토 | `?tab=review` | 현행 예약 관리 탭 | `summary.pendingCount`, 충돌·의심 합계 >0이면 ⚠︎ 점 병기 |
| ② 제출 준비 | `?tab=prepare` | 현행 제출 준비 탭 | candidates `summary.awaitingCount` — **조회 기간 기준** 명시 |
| ③ 제출 대기 | `?tab=ready` | 진행 중(REVIEWING) 배치만 | 전제 A3 (폴백: 건수 생략) |
| ④ 완료·보관 | `?tab=archive` | 완료+취소 배치 | 건수 표기 안 함 |
| (호환) | `pending→review`, `batches→ready`, `/submission→?tab=prepare` | 기존 URL 리다이렉트 유지 | |

- 페이지 헤더 우측 **크롤 신선도 칩** `● 학교 데이터 N분 전 수집`(전제 A1). 클릭 툴팁:
  "10분마다 자동 수집되고, 예약 상세를 열면 그 시점에 최신화됩니다." stale 시 코럴.
  목업의 "크롤 새로고침" 버튼은 신규 엔드포인트라 Out of Scope(§12).
- **PurposeNote**: 목업 배너를 채택하되 **1줄 컴팩트형**(아이콘+한 문장). 매일 보는
  화면에서 3줄 배너는 소음이다.
- **배지 통일**: 단일 StatusPill 로 통합. 예약 6종 라벨·색 현행 유지. 배치 배지만 라벨
  교체 — **"검토 중" → "제출 대기"**(검토할 것이 없는 상태에 "검토 중"은 오독 유발.
  목업 READY 채택).

## 2. 화면 ① 예약 검토

레이아웃(위→아래):
1. 워크플로 탭
2. PurposeNote: "예약을 검토해 승인 또는 거절합니다. 승인 건은 ② 제출 준비에 자동으로
   나타납니다."
3. **KPI 카드 4종 — 현행 유지**(승인 대기 / 학교 반영 대기 D+N / 충돌·의심 / 이달 확정,
   클릭=필터). 목업의 "오늘 이용 예정·이번 주 신청"으로 교체하지 않는다 — 현행 4종은
   전부 클릭 시 액션(필터)으로 이어지는 지표. 목업 2종은 후속 후보(§12).
4. 툴바: 상태 칩 5종(현행) + **건수 병기**(summary 재사용, UI-only. 건수 의미가 큐 필터와
   일치하는 칩에만: 승인 대기·반영 대기·충돌·의심) / 시설 select / 날짜 범위.
   동아리 검색은 P2 선택 항목(§11 A5).
5. **큐 그리드 테이블**:

| 컬럼 | 내용 | 비고 |
|---|---|---|
| 번호 | `#2094` (mono) | bookingId 표시 규칙, "R-" 접두 없음 |
| 동아리 · 목적 | 동아리명(굵게) / 목적 · 인원 N명 | 인원=전제 A2(폴백: 생략). 충돌 의심·부분 반영 인라인 pill 현행 유지 |
| 시설 | roomName | |
| 이용 일시 | `9.15 (월) 18:00~20:00` / 서브: `신청 9.13 21:04 · 2일 경과` | createdAt 기존 필드. APPROVED 는 경과 대신 `학교 반영 대기 D+N`(7일↑ 코럴) |
| 상태 | StatusPill | |
| 처리 | [검토] 버튼 | 행 전체 클릭도 동일 동작 — 버튼은 발견성·키보드 접근용 |

- 행 배경: CONFLICT 행만 옅은 코럴. PENDING 강조 배경은 두지 않는다(정렬이 이미
  오래된 순).
- 페이지네이션: 번호형 유지 + `1–20 / 42건` 범위 텍스트(totalElements 기존 값.
  충돌·의심 탭은 두 쿼리 병합이라 범위 비표기).
- Empty/로딩/에러: §9 공용 패턴.

## 3. 화면 ① 승인 상세 모달

폭 `max-w-lg → max-w-2xl`. 섹션 순서를 "판단에 필요한 순"으로 재배열:

1. **헤더**: 동아리명 + `#번호` + StatusPill / 서브 `시설 · 일시 · 목적 · N명 · 연락처`.
   거절 사유·충돌 상세는 해당 상태일 때 이 아래 경고 블록.
2. **크롤 신선도 배너** — 현행 유지. 카피 정비: "학교 데이터 기준 · 마지막 수집 N분 전.
   승인 시점에 이 데이터로 겹침을 검사합니다."(목업의 "재검증합니다"는 실제 동작—저장된
   스냅샷 검증—과 어긋남.)
3. **검증 3카드(신규, UI-only)** — 기존 응답 파생: 학교 일정 겹침(`overlaps[SCHOOL]`) /
   내부 승인 예약(`overlaps[INTERNAL]`) / 같은 시간대 대기(`overlappingPendingCount`).
   이상 없으면 ✓ "없음", 있으면 ⚠︎ + 건수. 운영자가 스트립 해석 전에 결론부터 준다.
4. **슬롯 스트립** — 현행 09–22 유지 + **겹침 칸에 점유 조직명 표기**
   (`overlaps[].organization`). 목업의 윈도우잉은 미채택 — 13칸이 이미 한 화면이고,
   잘라내면 다른 시간대 맥락을 잃는다.
5. **충돌 패널(조건부)** — 승인 409 시 현행 유지. 패널 안 [거절하기] 바로가기 추가
   (기존 거절 플로우 호출, 사유란에 충돌 내용 프리필). "대체 시간 추천"은 Out of Scope.
6. **같은 시간대 대기 안내** — 3카드로 흡수(중복 제거).
7. **처리 이력** — 데이터 현행(행위자 없음 — 노출 정책 미결로 Out of Scope). 표현만
   점+연결선 타임라인.
8. **액션 푸터 — 상태별 게이팅 현행 유지**(PENDING=승인·거절 / APPROVED=수동 확정·충돌
   전환·취소 / CONFLICT=재승인·취소 / CONFIRMED=취소). 파괴적 액션 좌측 분리, 주 액션
   우측. 사유 필수 다이얼로그·성공 토스트 현행 유지.

**신규 제안(목업에 없음): 대기 건 연속 검토.** 모달 헤더 [← 이전][다음 →](현재
필터·정렬 기준 큐 내 이동), 승인/거절 성공 토스트에 "다음 대기 건 열기" 액션. UI-only.

## 4. 화면 ② 제출 준비

**시설별 섹션 구조 유지**(배치=단일 시설 제약의 시각화). 그 위에 목업의 "버튼 하나"
UX를 얹는다:

1. PurposeNote: "승인된 예약이 자동으로 표시됩니다. 제외할 건만 해제하고 제출 목록을
   만드세요."
2. 후보 요약 카드 4종(클릭 필터) — 현행 유지.
3. 툴바 — 현행 유지(기간 ≤31일 + 동아리 검색 + 제출 상태 select + 목록/시간표 토글).
4. 시설별 섹션(클럽 아코디언/시간표) — 현행 유지. **섹션별 생성 버튼은 제거**하고 ↓로
   일원화.
5. **선택 요약 고정 바(신규)** — 하단 sticky: `선택 12건 · 시설 3곳 [전체 선택][전체
   해제] [제출 목록 만들기]`. 기본 전체 선택−제외 모델 현행 유지.
   [제출 목록 만들기] → **일괄 생성 다이얼로그**: 시설별 분해 행 + 시설별 메모 프리필
   `"M월 N주차 · 시설명"`(수정 가능). "배치는 시설 단위로 만들어져요. 메모는 목록
   이름으로 표시됩니다." **메모=목록 이름 승격** — name 컬럼 신설 없이 해결.
   생성은 기존 API 시설별 순차 호출. 부분 실패 시 성공/실패 시설 구분 표기.
6. **생성 완료 다이얼로그(신규)**: "제출 목록 N개가 만들어졌어요" + 배치별 [CSV 받기] +
   [③ 제출 대기로 이동]. 생성 직후 탭을 옮겨 배치를 다시 찾아 CSV 받는 동선 제거.

모바일: sticky 바는 기존 컨벤션(BottomNav 위 fixed, safe-area 보정, 푸터가 pb 소유) 준수.

## 5. 화면 ③ 제출 대기 (진행 중 배치)

REVIEWING 배치만(전제 A3). 컬럼: 제출 목록(**메모=제목** 굵게 / 서브 `제출번호 ·
생성자`, 메모 없으면 제출번호가 제목) / 시설 / 건수 / 생성일(+**생성 후 N일 경과** 서브,
3일↑ 앰버 — 방치 배치 감지, UI 계산) / 액션 [CSV][제출 완료][취소]. 행 클릭=상세.

- 액션 순서는 실제 작업 순서(CSV 준비 → 오프라인 제출 → 완료 처리). 상태 컬럼 없음.
- 완료 확인 다이얼로그: 현행 3불릿 유지 + **"학교 제출(오프라인)과 시스템 완료 처리는
  별개입니다. 실제 행정실 제출을 마친 뒤에 진행하세요"** 상단 경고 추가.
- 제외 결과 다이얼로그: 기능 현행, 표현만 건별 ✓/! 리스트 + "제외된 예약은 ② 제출
  준비에서 다시 담을 수 있습니다".

## 6. 화면 ④ 완료·보관

COMPLETED+CANCELLED(전제 A3). PurposeNote(gray): "완료·취소된 제출 기록입니다.
감사·정산 근거로 CSV를 다시 받을 수 있어요." 컬럼: 목록 / 시설 / 건수 /
완료일(취소 배치는 취소일) / 상태 / [CSV][상세]. 취소 배치 잔존·CSV 재다운로드 현행 유지.

## 7. 배치 상세 페이지

현행 구조(전용 페이지·읽기 전용 목록/시간표·운영 기록) 유지. 변경 2건: 헤더 제목을
메모(제목)로, 제출번호는 서브로. 액션 바 순서 [CSV][제출 완료][취소] 통일.

## 8. 다이얼로그 일람 (전부 기존 기능, 카피·비주얼 정비만)

| 다이얼로그 | 변경 |
|---|---|
| 일괄 생성(§4) | 신규 조합 — 기존 생성 API 재사용 |
| 생성 완료+CSV(§4) | 신규 조합 — 기존 CSV API 재사용 |
| 제출 완료 확인 | "두 행위 구분" 경고 추가 |
| 제외 결과 | 건별 리스트 비주얼 |
| 배치 취소 | 현행 유지 + "CSV는 계속 받을 수 있어요" 한 줄 |
| 예약 액션(사유 필수) | 현행 유지, 레이아웃 정비 |

## 9. Empty·로딩·에러 상태

공용 EmptyState(아이콘+제목+본문+이동 버튼) 도입. 로딩은 기존 컨벤션(LoadingGate·
delayed-show·버튼 라벨 유지+스피너) 그대로.

| 위치 | 제목 | 액션 |
|---|---|---|
| ① 필터 결과 없음 | "해당 조건의 신청이 없어요" | [필터 초기화] |
| ② 후보 없음 | "학교에 제출할 예약이 없어요" | [① 예약 검토로 이동] |
| ③ 진행 중 배치 없음 | "진행 중인 제출 목록이 없어요" | [② 제출 준비로 이동] |
| ④ 보관 없음 | "완료된 제출 기록이 없어요" | — |

## 10. 모바일

반응형 재배치 유지(전용 카드뷰는 Out of Scope). 워크플로 탭은 모바일에서 번호+현재
단계명만(비활성 단계는 번호만). 테이블 가로 스크롤+sticky 열, 다이얼로그 폭 현행 유지.
선택 요약 바는 §4 규칙.

## 12. Out of Scope

- 크롤 수동 새로고침 버튼(신규 엔드포인트+rate limit 설계 필요)
- 대체 시간 추천(경량판이라도 별도 설계)
- 처리 이력 행위자 노출(개인정보 노출 정책 결정 선행)
- 배치 정식 `name` 컬럼(메모 승격으로 대체)
- 혼합 시설 배치 허용
- KPI 신규 지표(오늘 이용 예정·이번 주 신청) / 학기 표기·필터
- 모바일 전용 카드 레이아웃
- 학생·동아리 측 화면 일체(변경 없음)
