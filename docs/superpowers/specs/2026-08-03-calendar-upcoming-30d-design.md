# 캘린더 Upcoming — 30일 창 + 모바일 타임라인 설계

2026-08-03 · 상태: 승인 대기

## 배경

`/calendar` 의 "UPCOMING · 다가오는 일정 / 이번 주, 놓치면 아쉬워요" 섹션은 제목과 실제 로직이
다르다. 코드와 실제 동작을 확인한 결과:

- 데이터는 `useCalendarMonthQuery(yearMonth)` 하나 — **지금 화면에 보이는 달**의 1일~말일만 조회한다.
- Upcoming 목록 = 그 달의 이벤트 중 `date >= today` → `sourceType-sourceId` 중복 제거 →
  날짜·시각 오름차순 → `slice(0, 6)`.
- **주(week) 계산 로직은 코드에 존재하지 않는다.**

실측(로컬, 오늘 2026-08-03):

| 확인 | 결과 |
| --- | --- |
| 8월 화면의 Upcoming | 1건 — **8월 31일, D-28** ("이번 주" 아래에 D-28) |
| 10월로 이동 | **0건** (제목만 남고 목록 없음) |
| 필터 칩 '모집 마감' 끄기 | 1건 → 0건 (칩과 연동됨) |
| 카드 탭 | **아무 동작 없음** — onClick/링크 없음, `cursor: auto`, "자세히 →" 는 죽은 어포던스 |
| 모바일 카드 높이 | **250px** → 6장이면 1,580px ≈ 가시영역의 2.2배 |

핵심 결함은 카피 불일치보다 **월 경계 절벽**이다. 8월 31일에 보면 9월 1~7일 일정이 한 건도 뜨지
않는다 — "다가오는 일정"이 가장 필요한 시점에 비어 버린다.

## 결정 사항 (사용자 확정)

- 조회 범위는 **오늘부터 30일**(양끝 포함), 최대 노출 **6개** 유지
  (14일은 현재 데이터 밀도에서 빈 상태가 잦다 — 8월 한 달 전체가 1건)
- **필터 칩(`activeKinds`) 연동은 유지**하고, 달(View) 과는 분리한다
- 모바일은 **Timeline List** 로 재설계 — 행 전체가 터치 영역, "자세히 →" 제거,
  탭하면 해당 일정 상세로 이동
- 데스크탑 UI 는 변경하지 않는다
- 조회 대상 월은 **고정 개수가 아니라 창에서 계산한 목록**으로 구한다
- 데이터 로직(`buildUpcoming`)과 표시 변환(`toUpcomingView`)을 모듈로 분리한다
- 모집 마감 API 는 **단기: 프론트에서 월별 조회 병합 / 장기: 백엔드 `from`·`to` 도입 후 통일(별도 PR)**

## 데이터 설계

### 30일 창이 걸치는 달은 1~3개다 (고정 2개 아님)

```
2026-08-03 + 30일 → 2026-09-02   months = [2026-08, 2026-09]
2026-12-31 + 30일 → 2027-01-30   months = [2026-12, 2027-01]
2027-01-31 + 30일 → 2027-03-02   months = [2027-01, 2027-02, 2027-03]   ← 2월이 통째로 들어간다
```

연 경계보다 **2월 경계가 함정**이다. "이번 달 + 다음 달" 고정이면 1월 말에 3월 초 일정이 누락된다.

### 훅 구조 — 월 목록을 받는 훅

월 개수가 1~3 으로 변하므로 훅을 반복 호출할 수 없다(Hooks 규칙). 월 목록을 인자로 받는 훅을 만든다.

```ts
// packages/hooks/src/calendarMonth.ts
export function useCalendarMonthsQuery(
  yearMonths: string[],
  options: { isAuthenticated: boolean; mappers: CalendarMappers },
): CalendarMonthResult;

// 기존 시그니처는 유지 — 내부에서 위 훅에 위임한다(그리드 호출처 무수정).
export function useCalendarMonthQuery(yearMonth: string, options: CalendarMonthOptions): CalendarMonthResult;
```

- 내부의 전역 행사·동아리 일정·모집 마감 조회를 모두 `useQueries` 로 옮겨 월 개수 가변을 허용한다.
- 전역 행사·동아리 일정은 이미 `{ from, to }` 를 받으므로 **월 목록의 첫 날 ~ 마지막 날**을 한 번에 조회해도 되지만,
  **쿼리 키를 월 단위로 유지**해야 그리드와 캐시가 겹친다(아래 참조). 월별로 나눠 조회한다.
- 모집 마감만 `yearMonth` 전용 API 라 월별 조회가 강제된다 — 단기 구현이 이 구조를 그대로 쓴다.

### 캐시 중첩 — 추가 요청이 대부분 0

Upcoming 은 **오늘 기준 월 목록**을, 그리드는 **보고 있는 달**을 조회한다. 쿼리 키가 월 단위로 같으므로
사용자가 이번 달을 보고 있는 동안 겹치는 달은 **네트워크 요청이 발생하지 않는다**. 다른 달을 보고 있을
때만 오늘 기준 월들이 추가로 붙는다.

### 목록 생성 규칙

```
events(월 목록 병합)
  → activeKinds 필터
  → todayIso <= date <= addDaysIso(todayIso, 30)      ← 30일 창(양끝 포함)
  → sourceType-sourceId 중복 제거(가장 이른 날짜 엔트리)
  → date ASC, time ASC
  → slice(0, 6)
```

`addDaysIso` 는 `@duing/hooks` 에 이미 있다(UTC 자정 파싱이라 월·연 경계 안전).

## 모듈 경계

```ts
// apps/web/app/calendar/_lib/upcoming.ts — 도메인만. 포맷 없음.
export function buildUpcoming(
  events: CalEvent[], todayIso: string, activeKinds: Set<EventKind>,
): CalEvent[];

// apps/web/app/calendar/_lib/upcomingView.ts — 표시만. 순수 함수.
export type UpcomingView = {
  dateLabel: string;      // '08.31'
  weekdayLabel: string;   // '월'
  dday: string;           // 'D-DAY' | 'D-28'
  title: string;
  placeLabel: string;     // '학생회관 302 · 여백'
  periodLabel: string | null; // 다일 이벤트 '6/5 ~ 6/10', 아니면 null
  kindLabel: string;      // '모집 마감'
  timeLabel: string;      // '23:59'
  accent: AccentStyle;
};
export function toUpcomingView(event: CalEvent, todayIso: string): UpcomingView;
```

데스크탑 카드와 모바일 타임라인은 **둘 다 `toUpcomingView` 결과만 소비**한다 — 날짜 표기·D-Day 가
갈라질 수 없다. 각 컴포넌트는 필요한 필드만 골라 쓴다(모바일은 `kindLabel`·`timeLabel` 미사용).

`D-Day` 계산은 현재 카드 안에 인라인 IIFE 로 들어 있는 로직을 그대로 옮긴다(로컬 자정 기준 일수 차).

## 모바일 Timeline List

```
┌─────────────────────────────────────────┐
│ UPCOMING · 다가오는 일정                 │
│ 앞으로 한 달, 놓치면 아쉬워요             │
├─────────────────────────────────────────┤
│  08.03  ●━┓  YEO BACK 정기 모임    D-DAY │
│    월     ┃  학생회관 302 · 여백          │
│  08.10  ○━┫  창업 아이디어 캠프     D-7  │
│    월     ┃  대구대 산학협력관             │
│  08.31  ○━┛  FLYING 모집 마감      D-28 │
│    월        지원폼 · FLYING              │
└─────────────────────────────────────────┘
```

- 행 = `<button type="button">`, 높이 **64~72px**(최소 터치 44px 상회), 전체가 탭 영역
- 탭 → 기존 `handleEventClick(event)` 재사용 = `setSelectedEvent` + `setEventDetailOpen(true)`.
  캘린더 상세 패널에서 일정을 탭하는 것과 **완전히 같은 경로**다. 새 라우팅·새 모달을 만들지 않는다.
- 레일 48px: `08.31`(15px 모노) / `월`(11px charcoal-3) / 종류별 도트(6px, `KIND_ACCENT` 색) + 1px 세로 라인
- 본문: 제목(14px/700, 1줄 말줄임) + 장소·동아리(12px charcoal-3, 1줄 말줄임)
- 우측: D-Day(12px 모노 700)
- 누르는 동안 `--cream-2` 배경(active 상태), 행 사이 1px `--gray-line`
- 데스크탑에서 노출하던 **카테고리 칩·시각·"자세히 →" 는 모바일에서 제거**
  (칩은 레일 도트 색이 대신하고, 시각은 상세 모달에서 확인 — 마감은 대부분 23:59 라 목록 정보량이 낮다)

높이 추정: 6건 × 68px + 헤더 ≈ **450px** (현재 1,580px 대비 약 1/3.5).

## 반응형 렌더링 — 양쪽 렌더 + CSS 숨김

| 방식 | SSR/하이드레이션 | 렌더 비용 | 유지보수 |
| --- | --- | --- | --- |
| **A. 양쪽 렌더 + CSS 숨김 (채택)** | 서버·클라 마크업 동일 → 위험 없음 | 6행 × 2벌, 행에 쿼리·이미지·옵서버 없음 → 무시 가능 | 마크업 2벌 (뷰모델 공유로 완화) |
| B. JS 미디어쿼리 조건부 렌더 | 서버는 뷰포트를 모름 → 기본값 렌더 후 교체 → **불일치 또는 첫 프레임 깜빡임** | 1벌(절약 미미) | 2벌 + 분기 로직 |
| C. 단일 마크업 CSS 변형 | 위험 없음 | 1벌 | **CSS 뒤틀림** — 두 뷰는 레이아웃뿐 아니라 정보 구성이 다르다 |

B 는 이 레포에서 특히 위험하다 — 모션 초기값을 SSR 에서 분기했다가 하이드레이션 불일치를 겪은 전례가
있어 "초기값은 상수 유지"가 규칙으로 남아 있다. 절약분이 행 6개 분량인데 대가가 첫 프레임 깜빡임이면
남는 장사가 아니다. C 는 모바일이 칩·시각·"자세히"를 덜어내므로 결국 숨김 노드를 안고 CSS 만 복잡해진다
(이 페이지가 `!important` 더미를 갖게 된 경로가 정확히 그것이다).

**주의(코드 주석으로 남긴다)**: 숨겨진 쪽도 React 렌더와 effect 는 돈다. 지금은 행에 부수효과가 없어
무해하지만, 행마다 옵서버·이미지가 붙으면 숨은 사본에서도 실행된다. 그때가 B/C 재검토 신호다.

## 카피

- eyebrow: `UPCOMING · 다가오는 일정` (유지)
- 제목: `이번 주, 놓치면 아쉬워요` → **`앞으로 한 달, 놓치면 아쉬워요`**
- 빈 상태 2종:
  - 필터 때문에 0건: `필터를 켜면 다가오는 일정을 볼 수 있어요`
  - 진짜 0건: `앞으로 한 달간 예정된 일정이 없어요`

## 엣지 케이스

| 상황 | 동작 |
| --- | --- |
| 1월 30·31일 | 창이 3개 달(1·2·3월)에 걸침 → 월 목록 3개 조회 |
| 12월 말 | 창이 2개 달(12월·다음 해 1월) → 연 경계 안전(`addDaysIso` UTC 파싱) |
| 다른 달을 보는 중 | Upcoming 은 **오늘 기준** 유지(뷰와 분리). 그리드만 그 달을 본다 |
| 필터 칩 전부 끔 | Upcoming 0건 + 필터 안내 문구 |
| 비로그인 | 동아리 일정 쿼리 skip(기존 동작) — 전역 행사·모집 마감만 노출 |
| 진행 중 다일 행사 | 오늘 이후 첫 엔트리가 선택됨. 그 엔트리에는 `span` 이 없어 기간 표기가 빠진다 — 기존과 동일, 이번 범위에서 고치지 않는다 |
| 30일째 / 31일째 | 30일째 포함, 31일째 제외(경계 테스트로 고정) |

## Out of Scope

- 데스크탑 카드 디자인 변경 (마크업 이동만, 시각적 변화 없음)
- 모집 마감 API 의 `from`/`to` 전환 — **별도 PR**. 전환 시 Upcoming 은 단일 range 조회로 접히고
  월 목록 계산이 사라진다. 대신 그리드와의 캐시 중첩이 사라지는 트레이드오프를 그때 판단한다
- 진행 중 다일 행사의 기간 표기 복원(P7)
- 캘린더 그리드·상세 시트·필터 칩 UI 변경
- 백엔드 변경 없음, 마이그레이션 없음
