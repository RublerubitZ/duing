# 홈 배너 섹션 반응형 위계 개선 — 설계서

- 날짜: 2026-06-20
- 대상 컴포넌트: `frontend/apps/web/app/_components/sections/BannerCarouselClient.tsx`
- 채택안: **A안 (중간 구간 2단 적층 + 큰 화면만 좌우 배치)**

## 배경 / 문제

홈 상단 배너는 메인 1장 + 보조 2장(다음 슬라이드 프리뷰)으로 구성된다. 현재 레이아웃은
`md(768px)` 이상에서 단일 그리드 `grid-cols-[1fr_340px]` 하나만 사용한다.

보조 컬럼이 **고정 `340px`** 이라, 컨테이너(`max-w-layout 1280px` + 좌우 패딩 40px + gap 16px)
기준으로 메인 폭은 `콘텐츠폭 − 356px` 이 된다.

| 뷰포트 | 메인 폭 | 보조 폭 | 메인:보조 | 상태 |
|--------|--------|--------|----------|------|
| 768px (md 시작) | 332px | 340px | 0.98 : 1 | 메인이 더 작음(역전) |
| 1024px (lg) | 588px | 340px | 1.73 : 1 | 위계 약함 |
| 1280px (xl) | 844px | 340px | 2.48 : 1 | 위계 명확 |

→ **768px ~ 약 1100px 구간**(노트북·작은 데스크톱·태블릿 가로)에서 메인이 보조와
같거나 더 작아져 위계가 무너진다.

추가로, 메인 배너는 `aspect-[24/8]`(3:1)이지만 grid 기본 `align-items: stretch` 때문에
보조 2장이 쌓인 컬럼 높이(약 308px)에 맞춰 늘어난다. 768px에선 메인이 `332×308` ≈ 거의
정사각형이 되어, 셋 다 "비슷한 크기의 카드"로 보인다 — 사용자가 지적한 *동일 카드처럼 보이는 현상*
의 직접 원인.

## 해결 (A안)

브레이크포인트별로 의도적으로 레이아웃을 재구성한다.

```
md 미만 (< 768px) : 메인만 (보조 숨김)              ← 모바일, 변경 없음 (범위 밖)
md ~ xl (768–1279): 메인 전체폭 상단 + 보조 2-up 하단  ← 신규 (중간 구간)
xl 이상 (≥ 1280) : 메인 + 보조 340px 컬럼 좌우       ← 기존 유지
```

핵심은 **하나의 그리드로 두 형태를 모두 표현**하는 것이다.

- 외곽 그리드: `grid gap-4 items-start xl:grid-cols-[1fr_340px]`
  - xl 미만 → 컬럼 미지정 = 단일 컬럼. 메인(1행, 전체폭) + 보조 컨테이너(2행, 전체폭)로 자연 적층.
  - xl 이상 → `[1fr_340px]` 2컬럼으로 기존 좌우 배치 복원.
  - `items-start` 로 **stretch 제거** → xl에서 메인이 보조 컬럼 높이로 늘어나지 않고 `aspect-[24/8]` 진짜 비율 유지.
- 보조 컨테이너: `hidden gap-3 md:grid md:grid-cols-2 xl:grid-cols-1`
  - md 미만 숨김(기존 유지) → md~xl 에서 2-up 가로, xl 에서 세로 1열.
- 메인 배너: `aspect-[2/1] sm:aspect-[24/8]` **유지**. 보조 프리뷰: `aspect-[85/37]`(가로형) **유지** —
  2-up 에서 자동으로 절반 폭으로 축소되어 "가로형 비율로 축소" 충족.

### 위계 보장 근거 (개선 후)

| 뷰포트 | 메인 | 보조(각) | 관계 |
|--------|------|---------|------|
| 768px | 전체폭 688 × ~229 (상단) | ~338 × ~147 (하단 2-up) | 메인이 폭 2배·상단 → 압도 |
| 1100px | 전체폭 1020 × ~340 (상단) | ~504 × ~219 (하단 2-up) | 메인이 폭 2배·상단 → 압도 |
| 1280px+ | 844 × ~281 (좌) | 340 × ~148 (우 세로) | 폭 2.48:1 → 압도 |

전 구간에서 "메인 → 보조" 시선 순서가 강제된다.

### CLS 방지

- 모든 박스가 `aspect-ratio` 로 높이를 선점 → 슬라이드는 SSR 주입이라 로딩 시프트 없음.
- 추가 안전장치로 메인 배너 래퍼에 자연 높이 이하의 `min-h` floor 를 둔다(왜곡 없이 붕괴 방지).
- xl 경계(1280px)에서의 적층↔좌우 전환은 창 리사이즈 시 의도된 리플로우이며 페이지 로드 CLS 가 아니다.

## 동작 보존 (불변식)

- 자동재생/스와이프/프리뷰 클릭(`onSelect`)/슬라이드 전환 애니메이션/하단 컨트롤 바 로직 — **변경 없음**.
- 보조 프리뷰 등장 애니메이션(`animate-preview-in` / `animationDelay`) — 컨테이너만 바뀌므로 그대로 동작.
- 모바일(md 미만) 내부 화살표·점 인디케이터 — 변경 없음.

## Out of Scope (이번 작업 제외)

- 모바일(< 768px) 레이아웃 — 별도 대응 완료, 손대지 않음.
- 캐러셀 동작 로직(자동재생 간격, 스와이프 임계값, 전환 타이밍).
- 슬라이드 콘텐츠/팔레트/타이포 토큰, 프로모션 데이터 모델·API.
- 보조 배너 개수(2장) 정책, 슬라이드 정렬/우선순위.
- 마케팅성 카피·CTA 문구 변경.
