# 시설 예약 패널 보완 3건 설계 (2026-07-16)

사용자 요구 3건 — 모두 `/facilities` 예약 패널(FE 단독, 백엔드 무변경).

## 1. 선택 날짜 예약 현황 요약 (PanelSummaryCard 확장)

날짜 선택 시 "이 날짜가 어떤 상태인지"를 패널 상단에서 즉시 읽을 수 있어야 한다.
기존 다크 요약 카드(레벨 배지·시간대 분포바·퀵 칩)는 유지하고 **상태별 집계 행**과 **운영 시간**을 추가한다.

- 집계는 `day.slots`에서 파생: 신청 가능(AVAILABLE) · 승인 대기(PENDING_HOLD) · 예약됨(BLOCKED) ·
  지난 시간(PAST). **0건 상태는 렌더하지 않는다**(지난 시간은 오늘에만 등장).
- 각 항목은 슬롯 리스트의 시각 언어와 정합하는 색 도트 + `라벨 N칸` 형식.
- 운영 시간은 `슬롯[0].start ~ 슬롯[마지막].end`로 파생해 표기(예: `운영 시간 09:00~22:00 · 13칸`) —
  FE 상수 하드코딩 금지(데이터 파생).
- 문구: INTERNAL/PENDING 동아리명 비노출 정책 유지 — 집계 라벨은 기존 슬롯 라벨("예약됨"/"승인 대기중")과
  동일 계열("예약됨"/"승인 대기").

## 2. 시간 선택 해제(Toggle) 버그 수정

**원인**: `toggleSlotSelection`(bookingCalendar.ts)이 "현재 선택이 정확히 그 단일 슬롯"일 때만 해제하고,
다중 슬롯 범위(예: 18:00~20:00) 내부 슬롯을 재탭하면 union(기존∪탭) = 기존 범위가 되어 그대로 반환된다.

**수정 규칙(단일 규칙)**: 탭한 슬롯이 현재 선택 범위 내부이면 **그 슬롯부터 끝까지 해제**한다.

- `tapped.start == current.start`(첫 슬롯 재탭) → 전체 해제(null)
- 그 외 내부 슬롯 재탭 → `{ start: current.start, end: tapped.start }`
  (마지막 슬롯 재탭 = 한 칸 축소, 중간 슬롯 재탭 = 그 지점까지 잘라냄)

선택이 "연속 범위 하나"라는 백엔드 계약과 정합하며, 선택(첫 탭→둘째 탭 확장)의 역동작이
탭 순서 역순 해제가 되어 대칭적이다. 범위 밖 탭의 기존 동작(연속·가능이면 확장, 아니면 그 슬롯로 재시작)과
단일 슬롯 재탭 해제는 무변경(후자는 새 규칙의 특수 케이스로 흡수).

## 3. 운영행(시간 범위 표기) 정책 안내

크롤 데이터의 "동아리명 (09:00~20:00)" 형태 운영행(OPERATING)은 슬롯을 차단하지 않는 정보 라벨이다
(어셈블러 정책 기존 그대로). 사용자가 "예약이 있는데 왜 신청이 되지?"라고 혼란하지 않도록,
`DaySlotList` 상단의 기존 한 줄 운영 표기를 **정책 설명이 붙은 안내 박스**로 승격한다.

- 운영행이 있는 날에만 렌더. 내용: 운영행 나열(단체명 + 시간 범위) + 정책 설명.
- 정책 설명 문구(고정): "시간 범위가 함께 표시된 일정은 운영상 확보된 시간 안내예요.
  이 시간에도 예약을 신청할 수 있고, 관리자 승인 후 학교 반영 절차를 거쳐 확정돼요."
- **승인 주체는 "관리자"로 통일**(기존 문구 정책 — 사용자 예시의 "총동연 승인"은 승인 주체 문구라
  치환 대상. 예상 시간 암시 금지도 유지).
- 모든 운영행에 동일 정책이 적용됨이 문구상 드러나야 한다("시간 범위가 함께 표시된 일정은" — 일반 서술).

## 4′. 예약 현황 리스트 목업 정합 + 퀵칩 제거 (2차 요구, 2026-07-16)

사용자 규칙: 새 디자인 금지 — Concept A JSX(`DAY_SLOTS`/`SLOT_STYLE`)의 표현 방식을 최대한 유지하고
필요한 부분만 조정한다. 기존 정책(운영행·HOLD 선택 가능·Rolling Window·비노출)은 전부 유지.

### 4′.1 슬롯 행을 SLOT_STYLE 시각 언어로

행 전체가 상태색을 입는다(현재: 흰 행 + 우측 회색 텍스트). 목업 ↔ 두잉 토큰 매핑:

| 상태 | 목업 | 두잉 토큰 (행 클래스) | 우측 표기 |
|---|---|---|---|
| AVAILABLE | free: sage-mist bg·sage-soft br | `border-sage-soft bg-sage-mist text-ink` + hover `border-sage` | "예약 가능" |
| PENDING_HOLD | pending: 앰버 계열 | `border-warm/60 bg-warm/15 text-charcoal-2` + hover `border-warm` | "승인 대기" |
| BLOCKED | booked: #F0EDE5(=graysoft) | `border-line bg-graysoft text-charcoal-3` | SCHOOL=단체명 / INTERNAL="예약됨" |
| PAST | closed(줄무늬) | `border-transparent bg-graysoft/60 text-charcoal-3` (기존 유지) | "지난 시간" |
| 선택됨 | mine: ink bg | `border-ink-deep bg-ink text-cream` (기존 유지) | ✓ + 기존 표기 |

**조정 사유 3건(목업 → 변경)**: ① closed 줄무늬 패턴은 raw hex gradient라 토큰 규칙과 충돌 —
PAST는 기존 muted 유지. ② pending fg #8E6620 은 팔레트에 없음 — warm 배경 + charcoal-2 텍스트로 대체.
③ 목업 pending 은 선택 불가처럼 보이나 두잉 HOLD 정책은 선택 가능 — hover 어포던스 유지, 폼의
기존 경고 문구가 후속 안내.

- 라벨 변경: "신청 가능" → **"예약 가능"**(목업·사용자 예시·캘린더 칩 "현재 예약 가능"과 통일),
  "승인 대기중" → **"승인 대기"**(사용자 명시). 요약 카드 집계 라벨도 "예약 가능"으로 동기화.
  다른 화면(manage 배지 등)은 booking status 도메인이라 무변경.
- 행 존재감 소폭 확대 허용(현황이 주 콘텐츠가 되도록) — 레이아웃 구조(단일 리스트·탭 선택)는 무변경.
  현황 확인과 시간 선택은 지금처럼 같은 리스트에서 이어진다(요구 4 충족 — 구조 변경 없음).

### 4′.2 "바로 신청 가능한 시간" 퀵칩 제거

- PanelSummaryCard 의 퀵칩 섹션(구분선 포함)과 `onQuickSelect` prop 제거. BookingPanel 호출부 정리.
- `firstAvailableStarts` 는 퀵칩 전용 → lib·테스트에서 삭제(dead code 금지 관례).
- 결과 구성: 날짜 요약(집계·운영 시간·분포) → 예약 현황 리스트(=시간 선택) → 선택 요약 → 신청.

## 4‴. 예약 건별 현황 카드 (4차 요구, 2026-07-16 — §4″ 대체)

§4″(슬롯 행 By 중심 스택)는 **사용자 반려로 폐기·롤백**됐다(revert 4a18d773·d230777e — 슬롯 행은
§4′ 상태로 유지). 사용자가 원한 것은 슬롯 행 변경이 아니라, **예약 건 단위 현황을 먼저 보여주는
별도 카드**다(목업 F2 "이 날짜의 예약 현황" 카드).

### 4‴.1 패널 구성 순서

날짜 요약(다크 카드) → **예약 현황 카드(신규)** → 기존 시간 슬롯 UI(§4′ 그대로, 무변경) → 신청 CTA.

### 4‴.2 예약 현황 카드 (목업 F2 카드 충실)

흰 카드(`rounded-lg border border-line bg-paper p-4`), 제목 `"{M월 d일} 예약 현황"`(13px bold).
**예약 하나 = 행 하나** — `day.slots`에서 파생하되 **연속 병합**한다(인접 슬롯이 같은 종류·같은
표기면 하나의 건으로: prev.end == next.start).

행 구성(목업 그대로): `시간 범위(mono, muted, 고정폭 w-[82px]) · 상태 도트(6px) · 이름(13px 600)`

| 종류 | 이름 표기 | 도트 | 비고 |
|---|---|---|---|
| BLOCKED+SCHOOL | 단체명 | `bg-charcoal-3` | 정책: 공개 단체명 |
| BLOCKED+INTERNAL | "예약됨" | `bg-charcoal-3` | 동아리명 비공개 정책 |
| PENDING_HOLD | "승인 대기" | `bg-warm` | 목업 "대기" pill 은 이름과 중복이라 생략 |

- 시간 표기는 기존 관례 `HH:MM~HH:MM`(rangeLabel 형식 — 목업 en-dash 대신 레포 통일).
- 마지막 행(점선 border-t 구분, 목업 그대로): `그 외 시간(mono, ink) · sage 도트 ·
  "예약 가능 · {availableSlotCount}개 시간"(bold ink)`.
- **예약 건이 0개면 카드 미렌더**(빈 카드 대신 슬롯 리스트가 바로 보이게 — 그 외 행만 남으면
  요약 카드 집계와 중복).
- PAST 로 덮인 지난 예약·운영행(OPERATING)은 현황에 포함하지 않는다 — 운영행은 기존 "운영 시간
  안내" 박스가 담당(§3 유지).
- 파생 헬퍼는 `bookingCalendar.ts`에 순수 함수로(`dayBookingEntries(slots)` —
  `{ start, end, label, kind: 'SCHOOL'|'INTERNAL'|'PENDING' }[]`), 카드는 신규 컴포넌트
  `DayBookingOverview.tsx`.

## 4⁗. 내부 예약 동아리명 노출 + 슬롯 행 흰 바탕 복원 (5차 요구, 2026-07-17)

### 4⁗.1 내부 예약 동아리명 노출 (백엔드 정책 반전 — 별도 PR)

현황 카드·슬롯 리스트의 "예약됨"(INTERNAL)에도 목업처럼 동아리명을 표기한다.

- **정책 반전(2026-07-17 사용자 결정)**: 공개 가용성 API가 INTERNAL(APPROVED·CONFIRMED) 차단
  슬롯에 동아리명을 내려준다. 근거 — 승인 완료 예약은 학교 반영 후 크롤(SCHOOL 행)로 어차피
  실명 공개되므로 새 정보가 아니다. 2026-07-13 비노출 결정은 이 범위에서 폐기.
- **PENDING(승인 대기)은 비노출 유지** — 아직 승인되지 않은 신청 경쟁 정보(§3.1 근거 유효).
- 백엔드: `GeneralFacilityAvailabilityService.toBookingSlices`가 차단 예약의 club 이름을 조회해
  `BookingSlice`에 싣고, 어셈블러 INTERNAL 분기가 `organization`으로 노출(blockedBy=INTERNAL 유지).
  PENDING 슬라이스는 계속 이름 없음. 관련 주석·테스트(비노출 단언)를 반전 결정으로 현행화.
- FE: `organization`이 있으면 소스(SCHOOL/INTERNAL) 무관 표기 — 없으면 "예약됨" 폴백
  (**fail-open**: 구 백엔드 응답에서도 동작, 배포 순서 자유. 단 이름 노출은 BE 배포 후).
  types 주석("SCHOOL만") 현행화.

### 4⁗.2 슬롯 행 흰 바탕 복원

§4′의 상태색 행 배경(sage-mist/warm/graysoft)을 **1차(원래) 시각으로 복원**한다 — 사용자 피드백
"흰 바탕이 낫다". 라벨 체계("예약 가능"/"승인 대기" 등 2차 확정 문구)와 병합·현황 카드는 유지.

- AVAILABLE·PENDING_HOLD(선택 가능): `border-line bg-paper hover:border-sage`
- 승인 대기 라벨 강조는 원래처럼 텍스트 색으로: PENDING_HOLD 라벨 `text-coral`
- BLOCKED·PAST(선택 불가): `border-transparent bg-graysoft/60 text-charcoal-3` (원래 muted)
- 선택 행 `border-ink bg-ink text-cream` + ✓ 유지. 현황 카드(§4‴)·운영 안내 박스(§3) 무변경.

## 4″. (폐기) 슬롯 행 정보 구조 — By(누가) 중심 전환 (3차 요구, 2026-07-16)

상태(Status)가 아니라 **예약 주체(By)가 메인 정보**가 되도록 행 구조를 바꾼다(Concept A `DAY_SLOTS`의
`by` 활용 요구). 시각 언어(§4′ 상태색 행·선택 ink·정책)는 전부 유지하고 행 내부 배치만 바뀐다.

### 4″.1 행 내부: 세로 스택 (시간 → 주 정보 → 배지)

사용자 명시 순서: `시간 ↓ 동아리명(있다면 가장 크게) ↓ 상태 Badge`.

- 1행: 시간 — `font-mono text-[11px]` 보조 톤(상태색 행의 muted 텍스트).
- 2행(주 정보, `text-sm font-bold`): **`organization ?? 상태 문구`**
  - BLOCKED+SCHOOL = 단체명(예: 비호응원단·트레몰로)
  - BLOCKED+INTERNAL = "예약됨" (동아리명 비공개 정책 유지)
  - PENDING_HOLD = "승인 대기" / AVAILABLE = "예약 가능" / PAST = "지난 시간"
- 3행(배지): **SCHOOL 행에만** 소형 pill "예약됨"(`rounded-full bg-paper/70 border border-line
  px-2 py-0.5 text-[10.5px] text-charcoal-3` 계열) — INTERNAL·PENDING 은 주 정보가 곧 상태라
  배지를 중복 표기하지 않는다("예약됨 (예약됨)" 방지). 선택된 행의 배지는 cream 계열로 반전.
- 모든 행이 동일한 스택 구조(사용자 예시의 인라인/스택 혼재 중 스택으로 통일 — 높이 리듬 일관).
  이름 없는 행은 2행까지만 렌더되므로 자연히 낮다.
- 선택 행: ink 배경 + 주 정보 앞 ✓ 유지. aria-label 은 "HH:MM~HH:MM 주정보" 순으로 갱신
  (SR 도 같은 정보 순서).
- 클릭·disabled·aria-pressed·운영 안내 박스·§4′ 행 배경색 전부 무변경.

## 5. 운영행 분할 타임라인 (6차 요구, 2026-07-17)

운영행("고정관념 (09:00~20:00)" 류 — 시간 범위가 함께 표시되는 크롤 행)은 예약 불가 일정이
아니라 **예약 가능한 운영 시간 구간**이다(기존 정책 그대로 — 슬롯 비차단·신청·확정 가능,
백엔드 무변경). 지금은 현황 카드에서 빠져 있는데, **현황 카드 타임라인에 포함하되 실제 예약이
차지한 구간을 잘라내고(Split) 앞/뒤 조각으로** 표시한다 — 예약 현황이 실사용 현황과 같아 보이게.

### 5.1 분할 규칙 (순수 함수 — FE 렌더링 전용)

- 입력: `day.operatingNotes[]` + 기존 예약 건(`dayBookingEntries` 결과 — BLOCKED·PENDING 병합).
- 운영 노트별로 시간순 겹침 절단: 커서=노트 시작 → 겹치는 예약 건마다
  `[커서, 예약.start)` 조각 생성 후 커서=max(커서, 예약.end) → 마지막에 `[커서, 노트 끝)` 조각.
  겹침 판정 `예약.start < 노트.end && 예약.end > 노트.start`.
- **분할 기준 = 현황 카드에 표시되는 모든 예약 행(BLOCKED+PENDING)**. 사용자 예시는 확정
  기준이지만, 승인 대기도 행으로 표시되므로 대기를 기준에서 빼면 타임라인에 시간 겹침이 생긴다
  — 겹침 없는 타임라인이 목적이므로 표시 행 전부를 기준으로 한다.
- 결과 타임라인 = 예약 건 + 운영 조각을 시작 시간순 정렬(동률이면 예약 건 먼저).
- 운영 노트가 여러 개면 각각 독립 분할(서로 겹치는 노트는 각자 조각 생성 — 수용).
- 예약이 노트 경계와 정확히 일치하면 해당 방향 조각은 생성하지 않는다(빈 구간 금지).

### 5.2 현황 카드 표기

- 운영 조각 행: 시간 범위 · **sage 도트**(예약 가능 구간이므로) · 단체명 + muted 접미
  `(운영 시간)`. 예약 건 행 표기는 기존 그대로.
- "그 외 시간 · 예약 가능 · N개" 행의 **N = AVAILABLE 슬롯 중 운영 노트 구간에 속하지 않는
  것만**(운영 구간도 예약 가능이므로 조각 행과 이중 집계 금지 — §4‴ 이중 계산 제거와 동일 원리).
  N=0이면 그 외 행 미렌더.
- 카드 미렌더 조건 갱신: **타임라인(예약 건+운영 조각)이 0건일 때만** 미렌더 — 운영행만 있는
  날도 카드가 뜬다(통짜 운영 조각 1행).
- "운영 시간 안내" 박스(§3 정책 문구)는 무변경 — 정책 설명 역할 유지.

## 4. Out of Scope

- 백엔드 변경(집계·운영 시간 전부 기존 응답에서 파생)
- WeekTimetable(주간 뷰)에 운영행 표기 추가
- 캘린더 월 셀의 운영행 표시
- 이용 안내 아코디언(페이지 하단) 문서 확장
- 슬롯 다중 비연속 선택(백엔드 계약 밖)
