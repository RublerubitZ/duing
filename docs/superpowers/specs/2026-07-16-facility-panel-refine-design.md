# 시설 예약 패널 보완 3건 설계 (2026-07-16)

사용자 요구 3건 — 모두 `/facilities` 예약 패널(FE 단독, 백엔드 무변경).

## 1. 선택 날짜 예약 현황 요약 (PanelSummaryCard 확장)

날짜 선택 시 "이 날짜가 어떤 상태인지"를 패널 상단에서 즉시 읽을 수 있어야 한다.
기존 다크 요약 카드(레벨 배지·시간대 분포바·퀵 칩)는 유지하고 **상태별 집계 행**과 **운영 시간**을 추가한다.

- 집계는 `day.slots`에서 파생: 신청 가능(AVAILABLE) · 승인 대기(PENDING_HOLD) · 예약됨(BLOCKED) ·
  지난 시간(PAST). **0건 상태는 렌더하지 않는다**(지난 시간은 오늘에만 등장).
- 각 항목은 슬롯 리스트의 시각 언어와 정합하는 색 도트 + `라벨 N칸` 형식.
- 운영 시간은 `슬롯[0].start ~ 슬롯[마지막].end`로 파생해 표기(예: `운영 시간 09:00~22:00 · 13칸`) —
  FE 상수 하드코딩 금지(데이터 파생).
- 문구: INTERNAL/PENDING 동아리명 비노출 정책 유지 — 집계 라벨은 기존 슬롯 라벨("예약됨"/"승인 대기중")과
  동일 계열("예약됨"/"승인 대기").

## 2. 시간 선택 해제(Toggle) 버그 수정

**원인**: `toggleSlotSelection`(bookingCalendar.ts)이 "현재 선택이 정확히 그 단일 슬롯"일 때만 해제하고,
다중 슬롯 범위(예: 18:00~20:00) 내부 슬롯을 재탭하면 union(기존∪탭) = 기존 범위가 되어 그대로 반환된다.

**수정 규칙(단일 규칙)**: 탭한 슬롯이 현재 선택 범위 내부이면 **그 슬롯부터 끝까지 해제**한다.

- `tapped.start == current.start`(첫 슬롯 재탭) → 전체 해제(null)
- 그 외 내부 슬롯 재탭 → `{ start: current.start, end: tapped.start }`
  (마지막 슬롯 재탭 = 한 칸 축소, 중간 슬롯 재탭 = 그 지점까지 잘라냄)

선택이 "연속 범위 하나"라는 백엔드 계약과 정합하며, 선택(첫 탭→둘째 탭 확장)의 역동작이
탭 순서 역순 해제가 되어 대칭적이다. 범위 밖 탭의 기존 동작(연속·가능이면 확장, 아니면 그 슬롯로 재시작)과
단일 슬롯 재탭 해제는 무변경(후자는 새 규칙의 특수 케이스로 흡수).

## 3. 운영행(시간 범위 표기) 정책 안내

크롤 데이터의 "동아리명 (09:00~20:00)" 형태 운영행(OPERATING)은 슬롯을 차단하지 않는 정보 라벨이다
(어셈블러 정책 기존 그대로). 사용자가 "예약이 있는데 왜 신청이 되지?"라고 혼란하지 않도록,
`DaySlotList` 상단의 기존 한 줄 운영 표기를 **정책 설명이 붙은 안내 박스**로 승격한다.

- 운영행이 있는 날에만 렌더. 내용: 운영행 나열(단체명 + 시간 범위) + 정책 설명.
- 정책 설명 문구(고정): "시간 범위가 함께 표시된 일정은 운영상 확보된 시간 안내예요.
  이 시간에도 예약을 신청할 수 있고, 관리자 승인 후 학교 반영 절차를 거쳐 확정돼요."
- **승인 주체는 "관리자"로 통일**(기존 문구 정책 — 사용자 예시의 "총동연 승인"은 승인 주체 문구라
  치환 대상. 예상 시간 암시 금지도 유지).
- 모든 운영행에 동일 정책이 적용됨이 문구상 드러나야 한다("시간 범위가 함께 표시된 일정은" — 일반 서술).

## 4. Out of Scope

- 백엔드 변경(집계·운영 시간 전부 기존 응답에서 파생)
- WeekTimetable(주간 뷰)에 운영행 표기 추가
- 캘린더 월 셀의 운영행 표시
- 이용 안내 아코디언(페이지 하단) 문서 확장
- 슬롯 다중 비연속 선택(백엔드 계약 밖)
