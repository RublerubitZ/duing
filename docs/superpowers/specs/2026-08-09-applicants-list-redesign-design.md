# 지원자 관리 목록 리디자인 — 설계

- 대상: `/manage/clubs/{clubId}/recruitments/{recruitmentId}/applicants` (목록 화면)
- 작성: 2026-08-09
- 선행: PR #939 (모바일 체크박스 히트 영역 44px·최종 상태 카드 정책)

## 1. 배경

운영 콘솔에서 **지원자 관리만 디자인 언어가 뒤처져 있다.** 회원 관리·모집 관리는 duing
토큰(`card` / `ink` / `charcoal` / `line` / `sage` / `cream`)과 칩 필터로 이미 개편됐는데, 지원자 관리는
`border-neutral-200` 컨테이너에 기본 `<select>` 4개가 한 줄로 늘어선 옛 형태로 남아 있다.

동시에 이 화면의 목적은 열람이 아니라 **처리**다. 운영진 동선은
`현황 파악 → 검색·필터 → 빠른 훑기 → 선택 → 일괄 처리 → (필요시) 상세`이며, 이 설계는 그 동선의
각 구간에서 걸리는 마찰을 없애는 것을 목표로 한다.

## 2. 실측 — 콘텐츠 폭이 뷰포트보다 훨씬 좁다

사이드바는 280px + 좌우 마진 12px(접으면 84px). 페이지 컨테이너 패딩까지 빼면:

| 뷰포트 | 실제 콘텐츠 폭 |
|---|---|
| 768 | 약 416px |
| 1024 | 약 672px |
| 1280 | 약 928px |
| 1440 | 약 1088px |
| 1920 | 약 1104px (`max-w-6xl` 상한) |

**전환 기준은 뷰포트다.** 사이드바를 접으면(84px) 콘텐츠가 196px 넓어지지만, 접힘 상태는 `ManageShell`
로컬 state + localStorage 라 자식이 알 수 없고 이 레포에는 컨테이너 쿼리 플러그인도 없다. 그래서
**펼침(최악)을 기준**으로 잡는다. 접힘에서는 여백이 남는 쪽으로만 어긋나므로 깨지지 않는다.

**표 컨테이너의 `overflow-x-auto` 는 유지한다.** "가로 스크롤을 만들지 않는다"는 *열 구성으로 폭을
맞춘다*는 뜻이지 컨테이너를 지우라는 뜻이 아니다. 지우면 예외적으로 긴 학과명 하나에 페이지 전체가
가로로 밀린다. 회원 관리도 `overflow-x-auto` + `min-w` 하한을 최후 방어선으로 남겨뒀다.

전체 열(선택·지원자·상태·학과/학년·단과대·학번·지원일·면접일정·내 평가)은 약 805px를 요구한다.
**1024px에서 표를 켜면 콘텐츠 672px에 805px를 밀어 넣게 된다** — 회원 관리와 같은 `lg` 전환만
따라가면 이 구간이 그대로 문제로 남는다. 그래서 전환점과 열 노출을 분리한다.

## 3. 반응형 정책

| 구간 | 뷰포트 | 콘텐츠 폭 | UI |
|---|---|---|---|
| 모바일·태블릿 | ~1023px | 432~671px | 2줄 dense list |
| 좁은 데스크탑 | 1024~1279px | 672~927px | 표 — Secondary 열(단과대·학번) 숨김 |
| 데스크탑 | 1280px~ | 928px~ | 표 — 전 열 노출 |

- 가로 스크롤은 만들지 않는다. 숨긴 열은 1280px 이상과 상세에서 볼 수 있다.
- 면접일정 열은 `useInterview=true`일 때만 존재한다(기존 동작 유지).
- 페이지 컨테이너를 `max-w-5xl` → `max-w-6xl`로 올려 회원 관리와 통일한다. 1920px에서도 1104px에서
  멈춰 정보 사이가 과도하게 벌어지지 않는다.

## 4. 모바일 — 2줄 dense list

```
┃ □  구승율 · 4학년                      [합격]
┃    AI학과 · 22028836              ●   08.09
```

- **1행**: 체크박스 / 이름 / 학년 / 상태 배지
- **2행**: 학과 / 학번 / 내 평가 여부 / 지원일(라벨 없이 값만)

### 높이 — 목표가 아니라 제약

카드 높이는 **고정 목표를 두지 않는다.** 44×44 히트 영역, 2줄 위계, 포커스 링, 가독성을 모두 만족하는
범위에서 가능한 한 줄인다. 계산상 61px(패딩 24 + 20 + 17)이 자연스럽게 나오면 그대로 쓰고, 빡빡하면
**65~72px까지 허용**한다. 판단 기준은 숫자가 아니라 "한 화면에 많이 보이되 터치성과 가독성이
상하지 않는가"다. 최종 수치는 실측으로 확정해 보고한다.

### 긴 텍스트 — 말줄임은 마지막 수단

중요한 정보가 잘려 사라지는 방식을 먼저 택하지 않는다. 순서는 다음과 같다.

1. **레이아웃으로 공간을 만든다** — 컨테이너에 `min-w-0`, 지원일·평가 표식처럼 폭이 고정된 요소는
   `shrink-0`으로 자리를 확보하고 나머지를 유연하게 둔다.
2. **축약 우선순위를 둔다** — 이름은 가능한 한 전체를 보여준다. 공간이 부족하면 학과명을 먼저 줄인다.
3. **말줄임은 마지막** — 320px에서 긴 학과명에 한해 허용한다. 이름 말줄임은 다른 수단이 모두
   소진됐을 때만 적용한다.

### 목록에서 생략하는 정보

| 항목 | 처리 | 확인 경로 |
|---|---|---|
| 단과대 | 생략 | 데스크탑 표 · 단과대 필터 · 상세 |
| 면접 일정 | 생략 | 상세 (목록에서는 "면접 대상" 배지가 단계를 알림) |
| 내 평가 **점수** | 생략 | 상세 |
| 내 평가 **여부** | **유지** — `●` | — |

`myScore !== null`을 "내 평가 작성됨"의 판정으로 쓴다. `ApplicationEvaluation.score`가 1~5 필수값이고
작성 폼이 항상 점수를 보내므로 "평가했으나 점수 없음" 상태는 존재하지 않는다.
점 하나만으로 의미를 전달하지 않도록 `aria-label="내 평가 작성됨"`을 준다.

### 상태 띠 (모바일 전용)

`border-l-4`로 카드 왼쪽에 상태색을 칠한다. 색은 기존 배지 색을 그대로 쓴다 —
지원 완료 sky / 보류 amber / 면접 대상 purple / 합격 emerald / 불합격 rose.

- 배지는 **유지**한다. 띠는 배지를 대체하지 않으며 색 단독으로 상태를 전달하지 않는다.
- 띠는 접근성 트리에서 제외한다.
- absolute overlay를 쓰지 않는다 — 카드 왼쪽 4px은 체크박스 히트 영역과 겹치는 자리라, 오버레이로
  그리면 #939에서 고친 오터치가 다른 형태로 되살아난다.
- **히트 영역 보정**: 테두리 4px이 생기므로 라벨의 음수 마진을 `-ml-3`(12px) → `-ml-4`(16px = 테두리
  4 + 패딩 12)로 바꿔야 44px이 카드 바깥 모서리부터 시작한다.

### 체크박스 (#939 정책 유지)

- 선택 가능: 44×44 라벨 히트 영역, 전파 차단, 시각 체크박스는 16px 유지
- 최종 상태(합격·불합격): 인터랙티브 라벨 없음 — 비활성 체크박스는 시각 표시만 하고
  `disabled:pointer-events-none`으로 탭이 카드까지 내려가 상세로 진입한다
- 2줄이 되어도 라벨의 마진박스는 20px(44-24)이고 콘텐츠 열이 37px이라 행 높이를 밀지 않는다

**두 동작의 분리는 실브라우저로 검증한다** — 2줄로 바뀌면서 히트 영역과 카드 본문의 기하가 달라지므로
jsdom 테스트만으로는 부족하다. 320 / 360 / 390 / 414px 각각에서 다음을 실측한다.

| 대상 | 탭 위치 | 기대 |
|---|---|---|
| 선택 가능 | 44px 영역 안 (모서리 포함) | 선택/해제만, 상세 이동 없음 |
| 선택 가능 | 카드 본문 | 상세 진입 |
| 최종 상태 | 체크박스 정중앙 | 상세 진입 |
| 최종 상태 | 체크박스 주변 44px 자리 | 상세 진입 |

## 5. 데스크탑 표

### 열 구성과 위계

`선택 | 지원자 | 상태 | 학과·학년 | 단과대 | 학번 | 지원일 | [면접일정] | 내 평가`

- Primary(이름·상태·학과/학년)와 Secondary(단과대·학번·지원일)의 시각 무게를 타이포로 분리한다 —
  이름은 `font-semibold text-ink-deep`, 보조 열은 `text-charcoal-3`, 숫자 열은 `tabular-nums`.
- 상태를 지원자 바로 옆에 둔다. 스캐닝에서 가장 자주 함께 읽는 두 값이다.
- 1024~1279px에서는 단과대·학번을 숨긴다.
- **내 평가 열은 데스크탑에서 기존대로 점수(`4 / 5`)를 유지한다.** 점 하나로 줄이는 것은 자리가 없는
  모바일에 한정된 축약이며, 표에는 점수를 담을 폭이 있고 점수 자체가 비교에 쓰인다.
- **지원일 열은 기존대로 날짜+시각(`지원일시`)을 유지한다.** 목록 정렬이 `createdAt desc` 라 같은 날
  지원자들의 순서 판단에 시각이 쓰인다. 날짜만 쓰는 축약은 자리가 없는 모바일에 한정한다.
- 빈 상태 문구(`검색 결과 없음` / `지원자가 아직 없습니다`)는 현재 동작을 유지한다.
- **상태 배지 팔레트는 현행(Tailwind sky/amber/purple/emerald/rose)을 유지한다.** `globals.css` 의
  `.pill-*` 세트는 4변형이라 5상태와 1:1 이 안 되고, 면접 라운드 마법사 등 다른 화면이 이 색에 맞춰
  동기화돼 있다(해당 파일 주석에 명시). 같은 상태가 화면마다 다른 색이 되는 쪽이 더 나쁘다.
- 숫자 열은 `tabular-nums` 로 자릿수를 맞춘다. 회원 관리는 날짜에 `font-mono` 를 쓰지만, 서체를 바꾸지
  않고 정렬만 얻는 쪽을 택한다.

### 상태 표현

**데스크탑에는 왼쪽 상태 띠를 넣지 않는다.** 독립된 상태 열과 배지가 이미 있고 행 높이가 낮아
4px 띠는 노이즈만 더한다. 대신 hover(`bg-cream/60`)와 선택 행 배경(`bg-cream/60`), 헤더
`bg-cream`으로 스캐닝을 돕는다. 회원 관리 표와 같은 값이다.

### 접근성 — 키보드로 상세에 갈 길을 만든다

지금 상세 진입은 `<tr onClick>` 과 `<div onClick>` 뿐이라 **키보드·스크린리더 사용자는 지원자 상세에
들어갈 방법이 없다.** 회원 관리는 이 문제를 상세 버튼으로 이미 풀어놨다.

이 화면은 **이름을 `next/link` 로 감싼다.** 열이나 버튼을 더하지 않고도 포커스 경로가 생기고, 실제
`href` 가 있어 새 탭 열기·가운데 클릭 같은 운영진에게 유용한 동작이 따라온다. 링크의 `href` 에는 행
클릭과 동일하게 현재 쿼리스트링을 붙이고, 링크 클릭이 행 `onClick` 과 겹쳐 두 번 이동하지 않도록 링크
쪽에서 전파를 끊는다. 표와 모바일 카드 모두 같은 방식으로 처리한다.

그 외: 체크박스 `aria-label` 유지, `focus-visible` 링, Space 토글, 선택 행 상태 표시, 칩 `aria-pressed`.

## 6. 검색·필터

### 상태 칩 + 카운트

```
[전체 34] [지원 완료 12] [보류 3] [면접 대상 8] [합격 10] [불합격 4]
```

- 라벨은 `APPLICATION_STATUS_LABEL`(운영진 라벨)을 그대로 쓴다. 배지와 칩이 같은 상태를 다른 이름으로
  부르지 않게 하기 위함이다. (스펙 초안의 "검토"·"면접"은 이 레포의 라벨이 아니다.)
- 면접 대상 칩은 `useInterview=true`일 때만 노출한다(상태 필터 옵션과 동일 규칙).
- **상태 칩은 단일 선택**이다 — `ApplicantsFilters.status` 가 단일 값이고 백엔드도 단일 enum 을 받는다.
  회원 관리의 `role` 칩(단일)과 같고 `flags` 칩(다중 토글)과 다르다. `전체` = `status: undefined`.

### 카운트는 목록에서 파생한다 (`stats/summary` 미사용)

`stats/summary` 는 **모집 전체 집계이며 어떤 필터도 받지 않는다.** 단과대·기간·검색어를 걸어 목록이
3건인데 칩이 `[합격 10]` 을 그대로 띄우면, 칩을 눌렀을 때 2건이 나오는 화면이 된다. 칩의 존재 이유가
"현황 + 필터" 인데 그 현황이 눈앞 목록과 어긋나면 정보가 아니라 오해가 된다.

그래서 **목록 API 를 `status` 없이 한 번 받아 클라이언트에서 상태별로 세고, 상태 필터도 클라이언트에서
적용한다.** 목록 API 는 페이지네이션 없이 전량을 주므로 가능하다. 이 선택의 효과는 다음과 같다.

- 칩 숫자가 **현재 걸린 다른 필터 안에서의 분포**가 되어 목록과 항상 일치한다.
- 상태 칩 전환에 네트워크 왕복이 없다 — 즉시 반응하고 목록이 사라졌다 나타나지 않는다.
- `stats/summary` 의존이 사라진다(신규 API 도, 추가 쿼리도 없다).
- **URL 의 `status` 파라미터는 그대로 유지한다.** 상세의 이전/다음 탐색은 서버가 같은 필터로 계산하므로
  이 파라미터가 사라지면 조용히 전체 목록 기준으로 움직인다.
- 나머지 필터(단과대·기간·검색어) 변경은 여전히 서버 요청이라, `useApplicantsQuery` 에
  `placeholderData: keepPreviousData` 를 넣고 갱신 중 딤 신호를 준다(`ClubExplorePage` 전례).

모집 관리 KPI 의 "검토 대기"(지원 완료+보류 합계)와 숫자가 다르게 보이는 것은 버킷 정의 차이이며,
필터와 1:1 인 이쪽 분해가 이 화면에서는 맞다.

### 모바일 — 칩 + 시트 하이브리드

```
┌────────────────────────────────┐
│ 🔍 이름·학번·학과         [필터 1]│
├────────────────────────────────┤
│ 전체34│지원완료12│보류3│면접8│… →│
└────────────────────────────────┘
```

- 상태 칩은 한 줄 가로 스크롤. **줄바꿈 금지** — 2줄로 접히면 목록이 아래로 밀린다.
- 단과대·지원 기간은 `[필터 N]` → 바텀시트. 상태는 시트에 중복해 넣지 않는다.
- 시트는 기존 `components/ui/sheet`의 `side="bottom"`을 쓴다(safe-area 패딩 포함).
- 적용된 필터 개수를 버튼에 표시하고, 시트 안에 초기화를 둔다.

### 데스크탑 — 전부 인라인

```
[ 🔍 이름·학번·학과 검색 ]
[전체 34] [지원 완료 12] [보류 3] [면접 대상 8] [합격 10] [불합격 4]
[단과대 ▾] [지원 기간 ▾]                              [초기화]
```

시트에 숨기지 않는다. 칩 스타일은 회원 관리 `MemberFilterChips`의 `CHIP_ON`/`CHIP_OFF`를 따른다.

## 7. 선택과 일괄 처리

### 전체 선택

**정의: 현재 필터 결과 중 선택 가능한 지원자 전원.** 목록 API가 페이지네이션 없이 필터 결과 전량을
주므로 "필터 결과 전체"와 "화면 전체"가 같다. 최종 상태(합격·불합격)는 선택 대상에서 제외한다.

| 상태 | 표시 |
|---|---|
| 미선택 | `□ 전체 선택 (14명 선택 가능)` |
| 부분 선택 | `— 전체 선택 (7/14)` |
| 전체 선택 | `✓ 전체 선택 (14명)` |

- indeterminate 는 회원 관리의 `useEffect` 로 `input.indeterminate` 를 세우는 방식을 따르되,
  **술어의 분모가 다르다.** 회원에는 선택 불가 행이 없어 `every(members)` 로 충분하지만, 지원자는
  최종 상태가 빠지므로 `every(selectable)` 이어야 한다. 그대로 복붙하면 **최종 상태가 한 건만 있어도
  `allSelected` 가 영원히 false** 가 되어 "전체 해제" 로 넘어가지 못한다. 표시 문구 `(7/14)` 의 분모도
  `selectable.length` 다.
- 데스크탑은 표 헤더 체크박스, 모바일·태블릿은 목록 위 한 줄에 둔다. 의미는 세 환경에서 동일하다.
  두 마크업은 CSS 로만 갈려 DOM 에는 늘 함께 있다 — 실제 접근성 트리에서는 `display:none` 쪽이 빠지지만,
  **jsdom 은 CSS 를 로드하지 않아 둘 다 잡힌다.** 페이지 단위 테스트는 컨테이너를 좁혀 조회한다.
- 선택 가능 인원이 0명이면 전체 선택 컨트롤을 비활성화한다. 목록이 0건이면 컨트롤 자체를 렌더하지 않는다.

### 필터를 바꿨을 때 선택의 생존

**상태·단과대·기간 변경 시 선택을 새 결과와의 교집합으로 정리하고, 검색어 변경은 선택을 건드리지
않는다.** 회원 관리가 이미 같은 규칙을 쓴다. 그냥 두면 "IT대 30명 전체 선택 → 단과대를 인문대로 변경 →
화면에 없는 30명이 선택된 채 일괄 불합격" 이 한 번의 오조작으로 가능해진다. 전체 선택을 도입하는
이번 변경이 이 구멍을 위험한 크기로 키우므로 함께 막는다.

일괄 처리 성공 후 선택 초기화는 현행(전량 초기화)을 유지한다.

### 일괄 처리

액션은 그대로 — 면접 대상으로 선정 / 보류 / 일괄 합격 / 일괄 불합격. sticky bottom bar 구조를
유지하되 콘솔 토큰으로 재도색한다(회원 관리 `MemberBulkToolbar`와 같은 골격).

**CLOSED 모집 정책은 절대 유지한다.** `finalizeOnly`일 때 되돌리는 액션(면접 대상 선정·보류)을 감추는
현재 로직을 세 환경 모두에 동일하게 적용한다. UI 단순화를 이유로 숨겨진 액션을 다시 노출하지 않는다.

## 9. 회귀 방지 대상

검색 / 상태·단과대·기간 필터 / 행 선택 / 다중 선택 / 면접 대상 / 보류 / 합격 / 불합격 /
CLOSED 액션 제한 / 상세 진입 / 상세 이전·다음 탐색.

특히 상세 진입 시 현재 필터를 쿼리스트링으로 넘기는 동작(이전/다음 탐색이 같은 필터 결과 안에서
움직이게 하는 근거)이 깨지지 않아야 한다. **URL 파라미터 이름 다섯 개(`status` / `college` / `q` /
`submittedFrom` / `submittedTo`)를 그대로 유지한다** — 칩·시트가 짧은 이름을 새로 쓰면 이전/다음이
에러 없이 전체 목록 기준으로 움직이는 조용한 오동작이 된다.

### 함께 갱신해야 하는 기존 테스트

`<select>` 를 칩으로 바꾸는 순간 깨지는 것들이다. 구현 착수 시점에 알고 있어야 한다.

- `applicants-filter-bar.test.tsx` — `getByRole('combobox', { name: '상태' })` 전제
- `closed-readonly.test.tsx` — `getByLabelText('상태')` 전제
- `applicant-card-touch.test.tsx` — 히트 영역 클래스 박제(`-ml-3`). 이 단언은 히트 영역이 조용히
  되돌아가는 것을 막으려고 #939 가 일부러 박아둔 것이다. **가드의 의도는 유지하고 값만 `-ml-4` 로 바꾼다.**
- `applicant-table-extension.test.tsx` — 옛 props(`selectedIds`/`onSelect`/`clubId`) 와 표+카드 동시 렌더 전제

### 페이지 나머지 요소의 재도색 범위

헤더·마감 배너·일괄 결과 알림·오류 문구·빈 상태·PII 푸터가 아직 `slate`/`neutral` 이다. 필터·표·카드만
토큰을 바꾸면 반쪽짜리 화면이 되므로, **같은 파일 안의 이 요소들도 콘솔 토큰으로 함께 옮긴다.**
문구·구조는 바꾸지 않고 색만 바꾼다.

## 10. 검증

- 모바일·태블릿: 320 / 360 / 375 / 390 / 414 / 768 — 가로 overflow 없음, 2줄 유지, 상태 띠, 배지,
  44px 히트 영역, 오터치 없음, 카드 본문 → 상세, 칩 가로 스크롤, 필터 시트, 전체 선택, 일괄 처리
- 데스크탑: 1024 / 1280 / 1440 / 1920 — 열 노출 규칙, 긴 이름·학과, hover·focus, 전체 선택과
  indeterminate, 일괄 처리, 빈 상태, 1440·1920에서 간격이 과도하지 않은지
- 시트에서 필터를 적용해 닫은 뒤 **뒤로가기 1회가 이전 화면으로 가는지** — 시트 닫기와 `router.replace`
  가 겹치는 자리라 오버레이 되찾기 문제가 날 수 있다
- 상태 칩 전환 시 목록이 사라졌다 나타나지 않는지(클라이언트 필터라 네트워크 없음), 검색어 변경 시
  이전 목록이 딤 처리로 유지되는지
- 각 구간에서 실브라우저 실측 결과를 최종 보고에 남긴다
