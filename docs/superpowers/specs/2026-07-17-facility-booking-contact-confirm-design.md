# 시설 예약 대표 연락처 + 신청 확인 Dialog 설계 (2026-07-17)

오예약(시설·날짜·시간·내용 실수)을 줄이기 위해 ① 신청 폼에 **대표 연락처** 입력란을 추가하고
② "예약 신청" 버튼이 즉시 전송하는 대신 **확인 Dialog**를 거치게 한다(사용자 12차 요구).
연락처는 저장·조회가 필요하므로 백엔드 확장(V85)을 수반한다 — 1차 UX 리프레시에서 이연했던
항목의 정식 반영.

## 1. 백엔드 — contact_phone (별도 PR, 먼저 머지)

- **V85 마이그레이션**: `facility_bookings`에 `contact_phone VARCHAR(20) NOT NULL DEFAULT ''`
  추가 후 DEFAULT 제거(기존 행 하위호환 — 기존 신청은 빈 문자열, 신규는 필수).
  기존 파일 수정 금지(새 파일만).
- **요청**: `CreateFacilityBookingRequest`에
  `@NotBlank(message = "대표 연락처를 입력해주세요.")`
  `@Pattern(regexp = "^01[016789]-?\\d{3,4}-?\\d{4}$", message = "휴대폰 번호 형식으로 입력해주세요.")`
  `String contactPhone` — command·entity·create 경로 관통.
- **노출 범위(PII 주의)**:
  - 관리자 큐/상세 응답 — 연락 용도(요구 취지). 기존 admin 응답 DTO에 필드 추가.
  - 동아리 관리(운영진) 상세 응답 — 본인 신청 확인용.
  - **공개 가용성·booking-window API 노출 절대 금지**(기존 비노출 정책 계열).
- 기존 행(빈 문자열)은 응답에서 null 로 내린다(blankToNull — FE "—" 표기 폴백).
- 테스트: 형식 검증(유효 2·무효 2), 저장·관리자 상세 노출, 공개 API 비노출 회귀.

## 2. 프론트 — 입력란 + 확인 Dialog (별도 PR)

### 2.1 대표 연락처 입력란

- BookingForm 의 "사용 인원(선택)" 아래 **"대표 연락처"**(필수) 입력. placeholder
  `연락 가능한 휴대폰 번호를 입력해주세요.` 도움말 문구: `관리자나 시설 담당자가 예약 관련
  연락이 필요할 때 사용해요.` FE 검증은 서버와 동일 패턴(하이픈 유무 허용), 오류 문구 한국어.
- 로그인 사용자 프로필(/users/me)에 휴대폰 번호가 있으면 **프리필**(편집 가능). 응답에 없으면
  빈 값 시작(확인 후 필드 부재 시 프리필 생략 — 구현 시 실제 응답 확인).
- payload 에 `contactPhone` 포함 — 구 백엔드는 unknown 필드 무시(머지 순서: BE 먼저 권장,
  역순이어도 에러 없음·저장만 안 됨).

### 2.2 신청 확인 Dialog

- 폼의 "예약 신청" 버튼 → 즉시 전송 대신 **Dialog**(components/ui/dialog 재사용, `.duing`
  스코프 재부여 전례). 폼 검증(필수·형식)은 Dialog 열기 전에 통과해야 한다.
- 내용(사용자 예시 준용):
  - 제목 "예약을 신청하시겠어요?" + 부제 "아래 내용을 다시 한번 확인해주세요."
  - 항목: 시설(roomName) · 예약 일시(`2026.07.28 (화)` + `14:00 ~ 16:00 (2시간)`) ·
    신청 동아리 · 사용 목적 · 사용 인원(미입력 시 "—") · 대표 연락처
  - 고정 안내: `예약 신청 후 관리자 승인과 학교 반영 절차를 거쳐 최종 예약이 확정됩니다.`
    (승인 주체 "관리자"·예상 시간 암시 금지 정책 정합)
  - 버튼: [취소] [예약 신청] — **실제 POST 는 Dialog 의 [예약 신청]에서만**. 제출 중 버튼
    비활성(중복 제출 방지), 409/에러 처리는 기존 경로 그대로(Dialog 닫고 기존 토스트/무효화).
- 접근성: DialogTitle/Description, 포커스 트랩은 Radix 기본.

### 2.3 관리자·관리 화면 표기

- 관리자 콘솔 상세와 동아리 관리 상세 모달에 "대표 연락처" 행 추가(값 없으면 "—").

## 3. Out of Scope

- 연락처 PII 파기 정책 연계(예약 데이터 보존 정책은 별도 논의 — 원장 기록)
- 시설 이용 수칙 동의 체크(목업 F4의 동의 박스 — 이연 유지)
- SMS 발송·연락 자동화
- gen:api 재생성(수동 타입 관례)
