## 1.5 PR-0 — 예약 오픈 구간 정책 (백엔드, 사용자 지시)

기존 "오늘~익월 말일" 창을 **반월(半月) 오픈 정책**으로 교체한다. 항상 "다음 예약 오픈 구간"만 신청 가능하다.

### 정책 규칙 (HALF_MONTH, pivotDay=15)
- 오늘이 1일~pivotDay(15일) → **당월 (pivotDay+1)일 ~ 말일** (예: 7/10 → 7/16~7/31)
- 오늘이 (pivotDay+1)일~말일 → **익월 1일 ~ pivotDay일** (예: 7/20 → 8/1~8/15)

### 설계 — 정책 계층 (하드코딩 금지, 확장 가능)
- `BookingWindowPolicy` 인터페이스: `BookingWindow windowFor(LocalDate today)` — `BookingWindow(from, until)` 값 객체.
- P1 구현: `HalfMonthBookingWindowPolicy(pivotDay)`. 확장 슬롯: `MONTHLY`(월 단위)·`FREE`(자유 기간)는 enum·설정 키만 예약(구현은 후속).
- 설정(환경변수 주입 가능, 시크릿 아님):
  - `duing.facility.booking.window.mode: HALF_MONTH` (enum: `HALF_MONTH | MONTHLY | FREE`)
  - `duing.facility.booking.window.pivot-day: 15` (검증: 1~27)
- 소비처 단일화: ① 가용성 응답의 `bookableFrom`/`bookableUntil` ② 신청 검증(`BookingPolicyValidator`의 날짜 범위 검사) — 둘 다 동일 정책 빈을 주입받는다(이중 정의 금지). 시간대 기준은 기존 관례(seoulClock/KST)를 따른다.
- **신규 공개 API**: `GET /api/v1/facilities/booking-window` → `{ bookableFrom, bookableUntil }` — 시설 카드 화면(시설 미선택 상태)이 오픈 구간을 표시하기 위한 전 시설 공통 값. availability 응답의 필드와 동일 정책 산출.
- 월 파라미터 검증(당월·익월만 허용)은 유지 — 반월 창은 항상 당월 또는 익월 안에 있다.
- 기존 통합 테스트의 날짜 픽스처는 "오늘 기준 창 내 날짜"를 계산하는 헬퍼로 전환(하드코딩 절대날짜 금지 유지).

### FE 반영 (PR-A에 포함)
- 캘린더 기본 표시 월 = `bookableFrom`의 월(오늘이 16일~말일이면 익월이 기본).
- 창 밖 날짜 셀: 시각적 비활성(디밍) + `aria-disabled`, **탭 시 토스트** "현재 예약 가능한 기간이 아니에요 (7.16 ~ 7.31)". 딥링크 `?date=`가 창 밖이면 패널을 열지 않고 동일 토스트.
- 캘린더 상단에 오픈 구간 상시 배지: "예약 가능 기간 7.16 ~ 7.31".
- 시설 카드에도 동일 구간 라벨(booking-window API — §2.2).

## 2. PR-A — `/facilities` 예약 홈 리프레시

단일 라우트·딥링크(`?facilityId=&date=`) 구조는 유지하고, **상태 기반 2뷰**로 재편한다.

### 2.1 뷰 구조
- **시설 선택 홈(F1)**: `facilityId` 미지정 시 노출. 헤더(RESERVE · 시설 예약 아이브로+타이틀+안내문) + 시설 카드 그리드(2~4열 반응형). 검색·카테고리 칩은 시설 10개 규모라 제외(P2). 카드 클릭 = 시설 선택(`?facilityId=` 세팅) → 캘린더 뷰 전환. **기존 "첫 시설 자동 선택" 제거** — 명시적 선택이 목업 의도.
- **캘린더 뷰(F2)**: `facilityId` 지정 시. 상단 **콘텍스트 바**(선택 시설 카드형 버튼 — 클릭 시 시설 홈 복귀 + 다른 시설 퀵 칩) + 월간 캘린더(히트맵) + 우측 패널/모바일 시트(기존 하이브리드·뷰포트 게이트 유지).
- 딥링크 하위 호환: `/facilities/[id]` redirect·`?date=` 복원 그대로.

### 2.2 시설 카드(F1)
- 아이콘 매핑(FE 상수): 커뮤니티룸→🛋(계열 공유), 공동연습실→🎸, 빛광장→🎤, 자유광장(노천강당)→🎪, 웅지관 강당→🏛, 미매핑→🏢. 커버는 이모지+sage 계열 그라데이션(목업의 시설별 색 대신 두잉 토큰 고정 — 임의 색 하드코딩 최소화).
- 본문: 시설명, 위치(nullable), "지금 사용중" 도트/뱃지(`isUsingNow`), **현재 예약 가능 기간 라벨**(예: "예약 가능 7.16 ~ 7.31" — booking-window API, 전 시설 공통이라 그리드 상단 1회 표기 + 카드 CTA 부근 보조 표기 중 구현 시 택일하되 사용자 요구는 "카드에서 바로 인지"이므로 카드 내 표기를 기본으로 한다).
- **정렬 기준(명시)**: usage API 응답 순서를 그대로 사용(백엔드 시설 마스터 순서), FE 재정렬 없음. 응답 순서가 비결정적이면 `facilityId` 오름차순으로 FE 고정.
- **오늘 가용 미니바**: `usage`의 `FacilityItem.reservations`(오늘 예약)로 파생 — 현재 시각 이후 남은 슬롯(09~22) 중 예약이 덮지 않은 수. `todayFreeSlotCount(facility, now)` 순수 함수 + 10칸 미니바 + "N개 시간 / 마감" 라벨. 22시 이후엔 "오늘 마감" 표기.
- CTA: "날짜 보기 →"(마감이어도 이동 가능 — 다른 날짜 예약이 목적이므로 목업의 disabled 처리 대신 항상 활성, 라벨만 구분).

### 2.3 월간 캘린더 히트맵(F2)
- 셀: 날짜 + **레벨 미니바(8칸)** + 레벨 라벨. 파생: `ratio = availableSlotCount / 13` → ≥0.6 여유(sage) / ≥0.3 보통(warm) / >0 혼잡(coral) / 0 마감(graysoft). 과거·범위 밖은 기존 dim 유지.
- 헤더에 범례(여유/보통/혼잡/마감), 오늘 셀 coral 링 유지, 선택 셀 ink 채움 유지.

### 2.4 Day View 패널 업그레이드(F2 사이드 + F3b 리스트)
패널(데스크탑 인라인/모바일 시트, 단일 제어 상태 유지) 내부를 3구역으로:
1. **다크 요약 카드**(ink 배경): 선택 날짜(큰 타이포)+레벨 뱃지, 오전(09–12)/오후(12–18)/저녁(18–22) 가용 분포 바(`slots` 파생), "바로 예약 가능한 시간" 퀵 칩(첫 가용 3개 + "+N" — 칩 탭=해당 슬롯 선택).
2. **슬롯 리스트**(F3b 스타일): `HH:mm~HH:mm` + 상태 라벨(신청 가능/예약됨/단체명(SCHOOL)/승인 대기/선택됨), 선택 슬롯 ink 채움+체크. 일간⇄주간 토글 유지. **주간 뷰 날짜 열 탭=일간 전환** + 선택일 컬럼 강조 테두리(셀 탭 슬롯 선택·범례는 §9.5 잔여 — FE3부터 이연, §4).
3. **선택 요약 + CTA**: `18:00–20:00` + "N시간" pill(sage-mist 박스), CTA "이 시간으로 신청", 하단 정책 문구(§1 조정 문구).

### 2.5 신청 확인·완료 단계
- 패널 내 단계 전환 구조 유지(slots→form→success). 폼은 목업 F4 스타일 섹션 카드("사용 정보": 동아리 셀렉트·목적 Preset 칩+입력·인원) + 상단에 예약 요약 블록(시설·날짜·시간·N시간). 패널 상단에 **미니 스텝 인디케이터**(시간 선택 → 신청 확인 → 승인 대기).
- **성공 화면 = F5 세로 타임라인**: ① 신청 접수(접수 시각 — 클라이언트 시각) ② 관리자 승인 대기(현재, warm 링) ③ 학교 예약 시스템 반영(승인 후 진행) ④ 예약 확정(크롤링 확인 후). + 겹침 대기 안내(기존 overlappingPendingCount 문구) + §1 조정 홀드 문구 + CTA 3개: 주 CTA "내 예약에서 확인"(manage 링크 — 기존 배선), 보조 **"다른 시설 예약하기"**(패널 닫고 시설 선택 홈으로 — facilityId·date 제거), "닫기".
- **승인 안내 문구 통일(전 화면)**: "관리자 승인 후 학교 반영 절차가 진행됩니다." — "보통 1~2일" 등 **예상 처리 시간을 암시하는 문구 전면 금지**(성공 화면·폼 안내·manage 상태 노트 공통).

### 2.6 유지·비변경

## 3. PR-B — manage 예약 목록 F6 리스킨

- 헤더: 아이브로("MY RESERVATIONS · 동아리 예약")+큰 타이틀. 탭 재편: **진행중 / 지난 예약** 2탭(+카운트 뱃지) — 진행중 = PENDING·APPROVED·CONFLICT + 미래(오늘 포함) CONFIRMED, 지난 = 과거 CONFIRMED·REJECTED·CANCELLED. (기존 4탭 대체 — 목업 구조 채택.)
- 카드(F6 FacResCard 스타일): 아이콘(시설 매핑 재사용)+시설명+상태 배지, 일시(mono), 목적 + **상태 노트**(PENDING "관리자 검토 중", APPROVED "승인됨 · 학교 반영 대기", CONFIRMED "예약 확정", CONFLICT "학교 예약과 충돌 — 다른 시간 신청 필요", REJECTED 사유 표시).
- CONFLICT 카드: coral 경고 박스(conflictDetail 있으면 표시) + **"다시 신청" CTA** → `/facilities?facilityId=` 딥링크. (목업의 "인접 시간 추천"은 P2.)
- 우측 액션: PENDING=취소(기존 확인 다이얼로그 재사용), 그 외=상세(기존 상세 모달 유지). 카드 본문 클릭=상세.
- 빈 상태·에러·예약 홈 CTA·페이지 가드(notFound) 기존 유지.
