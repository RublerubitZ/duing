# 회원가입 Step 1 (휴대폰 MO 인증) UI/UX 재설계 설계서

- 작성일: 2026-07-11
- 대상: `frontend/apps/web/app/(auth)/signup/_components/SignupStepVerify.tsx`, `.../PhoneVerificationField.tsx`, 신규 일러스트 컴포넌트
- 선행: 회원가입 2-step 리팩터(PR #623, 브랜치 `feat/signup-two-step`). 본 작업은 그 위에 Step 1의 **UI/UX만** 재구성한다.
- 배경: 현재 Step 1은 QR(128px)·인증코드·설명의 관계가 애매해 "무엇을 먼저 하지?"를 잠시 생각하게 한다. "**문자 한 통이면 인증이 끝난다**"를 3초 안에 이해되도록 재배치한다.

## 1. 목표

- **"QR 촬영 → 문자 전송 → 자동 인증 완료"** 흐름이 한눈에 읽히게 정보 위계를 재구성.
- 업로드된 안내 일러스트(`public/duing-signup.svg`)를 **인라인 SVG**로 통합해, 텍스트보다 먼저 개념을 전달.
- 기존 Auth 디자인 시스템(Sage Green / Cream / White Card / soft shadow)·기능·상태머신을 그대로 유지하고 **레이아웃/카피/일러스트만** 바꾼다.

## 2. 레이아웃 제약 (사이드바 · 공통 폭)

- `/signup`은 좌측 장식 사이드바(`<aside class="hidden lg:flex lg:w-[420px] xl:w-[480px] bg-ink-deep">`) + 우측 `SignupFormPanel`(`flex-1`) 구조. 사이드바는 `lg` 미만에서 숨김.
- 폼 콘텐츠는 패널 안에서 `max-w-[520px]` 로 중앙 정렬된다. **Step 1과 Step 2는 이 520px 공통 폭을 그대로 공유한다**(스텝 전환 시 폭이 튀지 않게). Step 1을 독립적으로 넓히지 않는다.
- 따라서 Step 1의 히어로·QR 카드는 **520px 안에서** 성립하도록 설계한다.
- QR vs 문자앱 딥링크 분기는 기존 `isMobileUserAgent(navigator.userAgent)` 기준(사이드바 브레이크포인트와 무관). 폰=딥링크, 데스크톱=QR 유지.

## 3. Step 1 구성 (위→아래)

520px 컬럼 안에서 다음 순서로 쌓는다:

1. **회원가입 pill + 스텝 인디케이터** — 현행 유지(①②).
2. **히어로 (단일 제목 블록)** — 배지류 없음(VERIFICATION·휴대폰 MO 인증 모두 제거). 구성: 큰 제목 `문자로 코드를 보내주세요` + 초록 강조 서브 `문자 한 통이면 본인 인증 끝` + **한 줄** 캡션 `수신번호로 그대로 전송하면 자동 인증 · 인증번호 입력 없음` + 인라인 일러스트 배너. (기존 히어로 제목 `휴대폰으로 본인 확인해요`와 메인 제목 `문자로 코드를 보내주세요`를 **하나로 통합** — 두 큰 제목 중복이 과하다는 피드백, 승인됨.)
   - 일러스트 배치: 제목·캡션 **아래 중앙 정렬 배너**로(≈320–400px, 원본 landscape 비율 유지). 정확한 크기·정렬은 구현·QA에서 520 폭에 맞춰 확정.
3. **인증 영역(상태별, 4절)**.

## 4. 상태별 UI

기능/상태머신(`usePhoneVerification`)·모바일 딥링크/PC QR 분기·폴링은 무변경. UI만 재배치.

### 4.1 idle (발급 전)
- 일러스트를 **가장 크게** 노출(개념 이해 순간). 히어로 + `휴대폰 번호` 입력 + `[인증 시작]` 버튼 + 한 줄 힌트.

### 4.2 issued / waiting (발급 후) — **데스크톱(QR 메인)**
- 발급 후엔 제목을 컴팩트 문구(`QR 찍고 문자만 보내면 끝`)로 바꾸고 **일러스트는 숨긴다** — 실제 QR/코드가 주인공이 되게 하고 일러스트의 예시 코드와 실제 코드의 혼동을 없앤다.
- 인증 카드(520 안 2단): **좌측 QR 확대(≈150–176px)** + **우측** `수신번호 1666-3538` · 코드(모노, `[코드 복사]`) · `남은 시간` · 흐름 캡션 `① QR 촬영 → ② 문자앱 → ③ 전송 → ✓ 자동 인증`.
- 하단 액션: `[문자를 보냈어요]`(primary) + `[재발급]`. 대기 중 `확인 중…`, stall 시 안내 + `[지금 확인]`(현행 로직 유지).

### 4.3 issued / waiting (발급 후) — **모바일(CTA 우선 · 점진 노출)**
- QR 없음. 코드/수신번호는 보조로 컴팩트 표시.
- **1차: `[문자앱으로 코드 보내기]` 단 하나만** 크게 노출(기존 SMS 딥링크). 버튼 과다 느낌 제거.
- **탭하면**: 문자 앱이 열리고(딥링크), **그때 비로소 `[문자를 보냈어요]` + `[재발급]`이 나타난다.** 최초 CTA는 보조 버튼 `[문자앱 다시 열기]`로 강등(재전송 대비).
  - `[문자앱으로 코드 보내기]` 탭 = 딥링크 열기 + 로컬 UI 상태 `linkOpened=true` 설정(노출 트리거). 폴링 시작은 아님.
  - `[문자를 보냈어요]` = 기존 `onSent()`(폴링 시작). `[재발급]` = 기존 `onIssue()`.
  - 딥링크가 안 열리는 기기 대비: 코드/수신번호를 보조 노출 + "버튼이 안 열리면 위 번호로 코드를 직접 문자 보내주세요" 안내.

### 4.4 verified
- `✓ 이 번호로 인증됐어요` + 번호 + (부모의) `[다음]`. 현행 유지, 톤만 디자인 시스템에 맞춤.

### 4.5 expired
- `시간이 초과됐어요. 다시 인증해주세요.` + `[다시 인증]`. 현행 유지.

## 5. 일러스트 통합

- **인라인 SVG 컴포넌트** 신규: `SignupIllustration.tsx` (`(auth)/signup/_components/`). `public/duing-signup.svg` 마크업을 JSX로 인라인(정적 프레젠테이션, `'use client'` 불필요).
- **viewBox `0 0 860 660`** 으로 확장 — 원본 파일은 `600`이라 폰 하단 ~50px가 잘림. 폰 전체가 보이도록 660 사용(승인된 결정).
- 색은 아트워크 고정값 유지(브랜드 팔레트와 일치: `#1F4A36`·`#2E8B57`·크림). 인증 화면은 `bg-cream` 라이트 전용이라 다크모드 대응 불필요.
- 일러스트 내 `1666-3538`·샘플 코드 `5WAVK4YZ`는 **설명용 고정값**(승인됨). 실제 수신번호·코드는 인증 카드에 별도 표시.
- **모션**: `prefers-reduced-motion` 존중. reduced 아닐 때만 은은한 진입/루프(예: 전송 버튼 미세 pulse). reduced면 정지. (하이드레이션 mismatch 방지: `initial` 상수 유지 — 기존 Framer 관례.)
- `public/duing-signup.svg`는 소스로 유지(컴포넌트가 인라인). 인라인이므로 런타임에서 파일을 참조하지 않는다.

## 6. 컴포넌트 · 변경 파일

- **신규** `_components/SignupIllustration.tsx` — 인라인 SVG(+옵션 모션). 프롭 없음 또는 `className`/`size` 정도.
- **수정** `_components/SignupStepVerify.tsx` — Step 1 래퍼. 히어로(배지 제거·카피 축약·일러스트) + 메인 안내 블록 추가, `PhoneVerificationField` 위에 배치. 상태에 따른 히어로 축소는 `verification.status` 파생값으로.
- **수정** `_components/PhoneVerificationField.tsx` — issued/waiting의 QR·코드·안내를 데스크톱 2단으로 재배치, 모바일 점진 노출(`linkOpened` 로컬 state) 적용. idle/verified/expired 카피·간격 정리. **로직·프롭 시그니처·상태머신은 유지**(모바일 점진 노출용 로컬 UI state만 추가).
- **무변경** `SignupFormPanel.tsx`(폭 520 유지), `SignupStepIndicator.tsx`, `SignupStepProfile.tsx`, `usePhoneVerification.ts`, `PhoneInput.tsx`.

## 7. 접근성

- 일러스트: 설명적 `<title>`/`aria-label`(예: "문자로 코드를 보내 본인 인증하는 방법 안내") 또는 순수 장식이면 `aria-hidden`. 핵심 안내는 실제 텍스트가 전달하므로 일러스트는 보조.
- 키보드: 모든 액션 버튼/링크 포커스 가능·논리적 탭 순서. 모바일 점진 노출로 새로 나타나는 버튼도 포커스 이동 자연스럽게.
- 상태 전이(`확인 중…`, stall 안내, 인증 완료)는 기존 `aria-live` 유지.
- QR `<img>`는 의미 있는 `alt`("문자 전송 QR").

## 8. 테스트

- 렌더: idle에 일러스트+`[인증 시작]`, issued에 (데스크톱)QR/코드/`[문자를 보냈어요]`.
- 모바일 점진 노출: `isMobileUserAgent`가 true인 환경에서 초기엔 `[문자앱으로 코드 보내기]`만 있고 `[문자를 보냈어요]`/`[재발급]` 부재 → CTA 탭 후 두 버튼 노출. (UA·`navigator` 목/스텁으로 제어.)
- 회귀: 기존 `PhoneVerificationField.test.tsx`·`use-phone-verification.test.tsx`·`SignupFormPanel.test.tsx` 그린 유지(폴링·stale·VERIFIED·2-step 흐름). 프롭 시그니처 무변경이라 통합 테스트 영향 최소.
- 일러스트 컴포넌트: 렌더 스모크(주요 텍스트/구조 존재).

## 9. Out of Scope

- Step 2(기본 정보)·로그인 페이지·백엔드(`signup`/MO 계약·인증 로직 자체).
- 공통 폼 폭(520) 변경, Step 2 레이아웃 변경.
- `usePhoneVerification` 상태머신·폴링·throttle·딥링크 생성 로직 변경.
- 사이드바(`<aside>`) 콘텐츠/폭 변경.
- SignupStepIndicator의 `aria-current` 시맨틱 보강(2-step 브랜치의 별도 deferred 항목 — 원하면 후속으로).
- 다크모드 대응(인증 화면은 라이트 전용).
- 만14세·마케팅 약관 등 신규 필드.
