# 회원 관리 리디자인 + 기수(Generation) 선택 기능

**Date:** 2026-07-24
**Scope:** 2-PR 스택 — PR-1 BE(`feat/members-generation-be`, V93) → PR-2 FE(`feat/members-redesign-fe`).

## 목표

회원 관리 페이지를 명단 조회 화면에서 **운영 허브**(조회→관리→운영)로 리디자인하고, 기수가 필요한
동아리만 선택적으로 쓰는 **기수 기능**을 추가한다. 기존 디자인 시스템·API·권한 정책을 최대한 재사용한다.

## 핵심 정책 (확정)

- **기수는 동아리 운영 정책** — 설정 위치는 **동아리 정보 페이지**(회원 관리 아님). 기본 OFF.
- **`use_generation` 은 순수 표시 제어** — 쓰기 게이트가 아니다. OFF 여도 기수 PATCH 는 항상 저장되고
  (silent failure 없음), 데이터는 보존되며, UI 만 전면 숨긴다(컬럼·필터·입력·상세·KPI — 기능 존재감 0).
- **휴면(Dormant) 전면 제외** — 데이터 모델 없음. KPI·필터·일괄·표시 어디에도 없음. 필터/KPI 배열이
  선언적 구조라 향후 항목 추가만으로 확장 가능하게만 설계.
- **회비는 회비 관리가 단일 SoT** — 회원 관리에서 수정·납부 처리 금지, "회비 관리에서 보기" 링크만.
- **역할 표기**: Enum(LEADER/OFFICER/MEMBER) 절대 불변. UI 라벨만 회장/**임원**/부원 — 라벨 유틸
  단일화로 기존 "운영진" 표기 전수 교체.
- **벌크 API 금지** — 일괄 작업은 기존 단건 API 반복 호출(FE), 진행·부분 실패 결과 표시.

## PR-1: Backend (V93, 순수 additive)

- **V93 마이그레이션**: `club.use_generation BOOLEAN NOT NULL DEFAULT false` +
  `club_member.generation INTEGER NULL`. **DB CHECK 없음** — 서비스 레벨 검증만: **양의 정수(≥1)**, 구체적 최대값은 스펙으로 고정하지 않음.
  기존 데이터 무영향(NULL 유지)·V92 이미지와 롤백 호환.
- **멤버 목록 응답 확장**(`ClubMemberQuery`): `generation`(nullable) + `feeStatus`(PAID/UNPAID/NONE).
  회비 판정 = 해당 club 의 유저별 **가장 최근 비-CANCELLED FeeBill(created_at, 동률 시 id)** 상태 —
  PAID→PAID, 그 외→UNPAID, 비-CANCELLED 청구 없으면 NONE.
  **단일 쿼리**(서브쿼리/윈도우) — 멤버당 N+1 금지.
- **기수 수정 API**: `PATCH /clubs/{clubId}/members/{memberId}/generation`(role PATCH 형제와 동일 프리픽스)
  body `{ generation: number | null }` — null=클리어(명시적). 검증: 양의 정수(서비스 레벨). use_generation
  무관하게 **항상 저장** — useGeneration 은 데이터 저장 여부가 아니라 **UI 표시 여부만 제어**(FE: true 일 때만
  기수 컬럼·필터·입력·상세 노출, false 면 전부 숨김).
- **설정**: `UpdateClubRequest`에 `useGeneration Boolean`(null=미변경 — clear-intent 규약) 추가,
  `ClubDetail` 응답에 `useGeneration` 노출(FE 회원·정보 페이지 공유, 민감정보 아님).
- 권한: 기수 PATCH 는 role PATCH·강퇴와 동일한 `requireLeader`(LEADER 전용·ACTIVE 클럽 — 구현 시 확정),
  목록 조회는 기존 LEADER/OFFICER 유지. 기존 API·Enum·권한 정책 무변경.

## PR-2: Frontend

### 동아리 정보 페이지
- "회원 기수 관리" 스위치 섹션(운영 정책 영역) — ON/OFF, OFF 시 안내 "기존 기수 데이터는 보존됩니다".

### 회원 관리 페이지 (재작성, 기존 디자인 시스템 재사용)
- **KPI 4종**: 재적 회원 / 임원(회장 1·임원 N 서브텍스트) / 회비 미납 / 조건부 4번째 —
  기수 ON: **"최신 기수"(최고 generation 인원 — "N기 X명" 표기, 신입=최고기수 가정 없음)** · OFF: "최근 가입"(기본 90일, **FE 상수** `RECENT_JOIN_DAYS` 로 관리).
- **필터 칩(조합 가능)**: 전체·회장·임원·부원·회비 미납·최근 가입·기수별(ON 일 때 드롭다운).
  선언적 배열 구조(향후 휴면 등 추가 대비).
- **검색**: 이름·학과·학번·기수(ON)·역할 통합, 결과 수 상시 표시.
- **목록**: 체크박스 / 이니셜 아바타+이름+학과·학년 / 역할 / 기수(조건부, "N기" 표기) / 회비(납부·미납·"—") /
  가입일 / 상세 버튼. **전화번호 목록 비노출**.
- **상세 패널**: 데스크탑 우측 고정 컬럼, **태블릿 Sheet(Drawer), 모바일 풀스크린**(기존 shadcn sheet/dialog).
  - 기본 정보: 이름·프로필·학과·학년·학번·**연락처(복사 버튼)**·가입일·**가입 기간(FE 계산, "2년 4개월")**·기수(조건부)
  - 운영 정보: 역할, 회비 상태(🟢 납부 / 🔴 미납 / ⚪ 관리 대상 아님 — 회비 기능 미사용·청구 이력 없음 모두 동일 정책) + "회비 관리에서 보기" 링크
  - 관리: 역할 변경 세그먼트, 기수 수정(ON), 기존 탈퇴·회장 이양 유지 — 회원 정보 수정 모달·회원 추가는
    없음(현 시스템에 해당 기능 자체가 없고 회원 정보는 본인 소유, 가입은 지원 플로우가 SoT)
- **일괄 툴바**: 선택 시 전환 — 임원 승급 / 부원 강등 / 기수 변경(ON) / 탈퇴(위험색 상시).
  단건 API 반복 호출, 진행 표시 + 부분 실패 요약.
- **CSV 내보내기**: **현재 적용된 검색·필터 결과 기준**으로 내보낸다(미납 필터 → 미납만, 기수 필터 → 해당 기수만.
  전체 명단은 필터 해제 후). 컬럼 확장(기수 ON 시 기수, 회비 상태). 확인 결과 CSV 생성은 이미
  프론트(export API 는 데이터만) — 필터된 memberId 집합으로 rows 를 걸러 생성한다.

## 테스트

- BE 통합: 기수 PATCH(저장·클리어·범위 400·OFF 에서도 저장), useGeneration 설정(null=미변경),
  목록 feeStatus 3상태(최신 청구 기준·청구 없음 NONE), 목록 쿼리 수 고정(N+1 가드), 타 클럽 404.
- FE 단위: ON/OFF 조건부 렌더(컬럼·필터·입력·KPI 4번째 전환), 필터 조합·검색 결과 수, 일괄 부분 실패 요약,
  가입 기간 계산, 역할 라벨 유틸(임원), 복사 버튼.
- 실브라우저 QA: 반응형 3단(고정 컬럼→Sheet→풀스크린), 기수 토글 실전환(정보 페이지↔회원 페이지),
  CSV 다운로드 내용, 일괄 작업 실흐름.

## Out of Scope

- 휴면 상태(모델·정책·UI 일체), 최근 로그인·마지막 활동, 자유 컬럼 표시 토글, 벌크 API,
  회비 수정·납부 처리(SoT=회비 관리), Excel 내보내기(CSV 만), 회원 커스텀 필드(generation 은
  단일 컬럼으로 단순 유지 — 커스텀 필드 필요 시 별도 설계), 학생 측 화면 변화 없음.
